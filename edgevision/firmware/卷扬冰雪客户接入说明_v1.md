| --- | --- |
| 文档版本 | v1.0 |
| 更新日期 | 2026-10-22 |
| 适用功能 | 卷扬冰雪（功能模块号 `0x0008`） |

本文面向使用预编译动态库接入卷扬冰雪功能的客户工程师，说明如何在板上运行 demo、在自己的程序中调用接口，以及如何读取结果和排查问题。

**当前只有卷扬模型，尚未接入冰雪模型。`result_code` 和 `snow_detections` 暂按卷扬输出。`snow_detections` 保留未经置信度阈值过滤、未经 NMS 的合法卷扬候选，包括零分候选；冰雪候选面积由卷扬框内的 HSV 颜色统计估算。**

除特别说明外，本文的文件路径和命令均相对解压后的 SDK 根目录。先按第3节跑通样例，再按第4节接入自己的程序；完整字段定义见第5节。

## 1. 适用范围与验证环境

- 核心库为 `libevs_core.so.1`，卷扬冰雪库为 `libevs_ice.so.1`，两个库配套使用。
- 检测入口是 `evs::winch_ice::Detector`，公开头文件是 `evs/winch_ice.h`。
- 库同步处理调用方传入的一帧图像，返回候选框、筛选后的卷扬对象、面积占比和本帧报警状态。
- 相机取流、BGR/NV12转换、工况判断、重试和报警保持由客户程序负责。
- 本包配套模型和二进制已在RK3588验证，其他芯片或系统环境需单独适配、验证。

| 项目 | 已验证环境 |
| --- | --- |
| 芯片 / 架构 | RK3588 / ARM64（aarch64） |
| 操作系统 | Ubuntu 22.04.5 LTS |
| Linux内核 | 5.10.209-rk3588 |
| 接口语言 | C++17 |
| 编译器 | g++ 11.4.0 |
| CMake | 3.22.1，用于编译完整demo |
| glibc | 2.35 |
| OpenCV | 4.5.4，运行依赖core和imgproc库 |
| RKNN Runtime | 板端配套的librknnrt.so，校验值见VERSION.json |

运行时需要SDK中的两个EVS库、配套模型，以及设备上的RKNN、OpenCV和C/C++运行库。系统运行库不随本SDK打包。直接运行已编译demo不需要编译器或CMake；自行编译示例需要g++，编译完整demo还需要CMake。示例不需要RKNN或OpenCV开发头文件。

## 3. 快速跑通

### 3.1 准备

进入SDK根目录，先检查文件和动态库依赖：

```bash
sha256sum -c SHA256SUMS
ldd bin/winch_ice_api_demo
```

文件校验应全部通过，`ldd` 不应出现 `not found`。`libevs_core.so.1`、`libevs_ice.so.1` 应从本SDK的 `lib/` 加载。

### 3.2 执行

以下输出目录必须尚未存在；重复运行请更换目录名。

```bash
# 默认检测
./bin/winch_ice_api_demo configs/winch_ice.yaml demo/sample.ppm --out /tmp/winch_ice_default

# 初始化后更新面积阈值，并注册日志回调
./bin/winch_ice_api_demo configs/winch_ice.yaml demo/sample.ppm --area-ratio 0.1 --log-callback --out /tmp/winch_ice_alarm

# 将置信度阈值改为1，查看候选输出与筛选结果的区别
./bin/winch_ice_api_demo configs/winch_ice.yaml demo/sample.ppm --confidence-threshold 1 --out /tmp/winch_ice_high
```

### 3.3 成功标志

默认样例运行成功时，进程退出码为0，终端显示 `Run record:` 及记录目录。完整demo会将标准输出、标准错误和检测结果保存到该目录的 `run.log`，其中应包含：

```text
frame=1 result_code=1 alert_level=0 winch_candidates=7146 objects=1
```

可在默认命令运行完成后查看：

```bash
cat /tmp/winch_ice_default/run.log
```

成功处理样例后，输出目录中应有输入图、`frame_000001.png`、`frame_000001.json`、`result.json` 和 `run.log`。画框图显示筛选后的卷扬框，JSON保存完整候选及接口输入输出。流程中途失败时只保留已生成文件；参数或目录创建阶段失败时，可能没有运行记录。

以上数量只对应本包704×576样例。其他图片应先以接口是否成功为准，再判断业务结果，不能要求每张图都检测出卷扬。

### 3.4 参数与退出码

完整demo的前两个参数为位置参数：

```text
winch_ice_api_demo config.yaml image.ppm [选项]
```

| 参数 | 含义 | 默认 / 范围 |
| --- | --- | --- |
| config.yaml | 示例配置路径 | 必填；模型相对路径按YAML所在目录解析 |
| image.ppm | 输入图片路径 | 必填；P6/255 PPM |
| --out DIR | 新建的留档目录 | 省略时在当前目录的records下创建新目录 |
| --area-ratio N | 初始化后通过updateConfig更新面积报警阈值 | [0,1]；省略则沿用配置 |
| --confidence-threshold N | 初始化后通过updateConfig更新卷扬筛选阈值 | [0,1]；不筛选snow_detections |
| --repeat N | 对同一图片连续检测N次 | 默认1，范围1～10000；不是相机取流 |
| --log-callback | 注册宿主日志回调，消息写入控制台留档 | 默认不注册 |

模型路径和NMS阈值在YAML中设置；不带参数运行会打印usage。

| 完整demo退出码 | 含义 |
| --- | --- |
| 0 | 本次流程完成 |
| 1 | 参数解析、读写或接口调用等失败，结合控制台和已生成记录排查 |
| 2 | 未提供两个必需的位置参数，打印usage |

命令行demo读取PPM文件；直接调用API传图像内存，不要求使用PPM或YAML。

## 4. 接入自己的程序

### 4.1 接入约束

1. 同一实例的方法与析构须串行执行，共用同一模型的不同实例也统一串行调度；不要在检测尚未返回时释放实例。
2. 图像缓冲区由调用方持有，至少保持到 `detect` 返回。接口没有缓冲区长度字段，调用方须保证实际分配长度足够。
3. 输入只支持紧凑RGB24或8位灰度。BGR、NV12及带行填充的图像先转换、整理，不能直接传入。
4. 相机ID在初始化配置的 `camera_channel` 中设置，`ImageData` 不另传相机ID；`timestamp_ms` 单位是毫秒。
5. 先检查接口返回码，再读取业务结果。返回0表示调用成功，不表示检出冰雪或应该报警。
6. 检测仅需 `evs/winch_ice.h`。即使客户程序不使用OpenCV，板端仍需配套OpenCV运行库；编译本包示例无需OpenCV开发头文件。
7. 已返回的结果由调用方持有，跨线程读取时自行同步；release不会自动清除调用方保存的旧结果。

### 4.2 准备配置并初始化

下面是函数内调用片段，处理函数返回 `ErrorCode`，初始化失败时立即返回错误码；`#include` 放在源文件顶部。完整可编译程序见第4.5节。

```cpp
#include <evs/winch_ice.h>

using namespace evs::winch_ice;
WinchSnowConfig config;
config.model_config.Model_path = "/opt/edgevision/models/winch_model.rknn";
config.model_config.input_width = 640;
config.model_config.input_height = 640;
config.model_config.warmup = false;
config.detect_config.confidence_threshold = 0.45f;
config.detect_config.nms_threshold = 0.5f;
config.detect_config.area_ratio = 0.5f;
config.camera_channel = 0;

Detector detector;
const ErrorCode init_status = detector.initialize(config);
if (init_status != 0) {
    return init_status;
}
```

模型路径应改成实际部署位置。直接构造配置时，相对模型路径按进程工作目录解释，推荐使用绝对路径。模型输入尺寸为640×640，不要求相机原图也是这个尺寸。

构造后实例未初始化，初始化成功后才能调用detect/updateConfig。已初始化时重复initialize返回0，继续使用原配置；换模型、输入规格或相机时先release，再initialize。release可重复调用，析构也会清理资源，实例不可拷贝或移动。

### 4.3 每帧输入与结果读取

下面的 `rgb_data`、`width`、`height` 和 `timestamp_ms` 由客户取流程序提供，`detector` 是已成功初始化的实例：

```cpp
ImageData image;
image.data = rgb_data;
image.width = width;
image.height = height;
image.channels = 3;
image.timestamp_ms = timestamp_ms;

WinchSnowResult result;
const auto detect_status = detector.detect(image, result);
if (detect_status == 0) {
    // result.snow_detections：完整合法候选，包括低分和零分框。
    // result.objects：置信度筛选、NMS后的卷扬对象。
    // 只在object.valid为true时使用object.ice_ratio。
    // result.alert_level：本帧是否有有效对象达到面积阈值。
} else {
    // 本帧失败，记录detect_status，不读取业务输出，不沿用旧帧结论。
}
```

每次调用都处理传入图像，包括时间戳重复的图像。库没有报警锁存、多帧滤波或停止检测策略，这些由客户程序实现。

### 4.4 更新阈值

初始化成功后，可复制当前配置，只改需要调整的字段，再整体传入三个阈值：

```cpp
auto next = config.detect_config;
next.area_ratio = 0.1f;
if (detector.updateConfig(next) == 0) {
    config.detect_config = next;
}
```

成功后新阈值用于后续detect；失败时原配置保留。不要用新建的默认DetectConfig无意覆盖另外两个已调整的阈值。

### 4.5 最小可运行示例

SDK内 `demo/minimal.cpp` 的完整代码如下，已在RK3588上独立编译运行。它只读取包内的固定尺寸 `sample.ppm`，演示无需YAML或日志回调的接入流程。接相机时，替换读样例部分，保留配置、ImageData和Detector调用。

```cpp
#include <evs/winch_ice.h>
#include <cstdio>
#include <exception>
#include <fstream>
#include <string>
#include <vector>

int main(int argc, char** argv) {
    if (argc != 3) {
        std::fprintf(stderr, "usage: %s model.rknn demo/sample.ppm\n", argv[0]);
        return 2;
    }
    try {
        // 只读取本包的 704x576 PPM 样例。接相机时，用自己的 RGB 缓冲区填写 ImageData。
        constexpr uint32_t width = 704, height = 576;
        std::ifstream input(argv[2], std::ios::binary);
        std::string first, second, third;
        if (!std::getline(input, first) || !std::getline(input, second) ||
            !std::getline(input, third) || first != "P6" || second != "704 576" || third != "255") {
            std::fprintf(stderr, "expected the SDK's 704x576 demo/sample.ppm\n");
            return 2;
        }
        std::vector<uint8_t> rgb(size_t(width) * height * 3);
        if (!input.read(reinterpret_cast<char*>(rgb.data()), rgb.size())) {
            std::fprintf(stderr, "sample image is incomplete\n");
            return 2;
        }

        using namespace evs::winch_ice;
        WinchSnowConfig config;
        config.model_config.Model_path = argv[1];
        config.model_config.input_width = 640;
        config.model_config.input_height = 640;
        config.camera_channel = 0;
        // 三个检测阈值使用默认值 0.45、0.5、0.5；不需要 YAML 或 load_config。
        Detector detector;
        auto status = detector.initialize(config);
        if (status != 0) {
            std::fprintf(stderr, "initialize failed: 0x%08X\n", static_cast<unsigned>(status));
            return 1;
        }

        ImageData image;
        image.data = rgb.data();
        image.width = width;
        image.height = height;
        image.channels = 3; // 紧凑 RGB24，缓冲区至少保持到 detect 返回。
        WinchSnowResult result;
        status = detector.detect(image, result);
        if (status != 0) {
            std::fprintf(stderr, "detect failed: 0x%08X\n", static_cast<unsigned>(status));
            detector.release();
            return 1; // 失败时不读取业务结果。
        }

        std::printf("result_code=%d alert_level=%d winch_candidates=%zu objects=%zu\n",
                    static_cast<int>(result.result_code), static_cast<int>(result.alert_level),
                    result.snow_detections.size(), result.objects.size());
        // snow_detections 已返回完整候选；此例只打印数量和筛选后的卷扬对象。
        for (size_t i = 0; i < result.objects.size(); ++i) {
            const auto& object = result.objects[i];
            const auto& box = object.box;
            std::printf("object[%zu] class_id=%u confidence=%.9g x=%u y=%u width=%u height=%u valid=%d",
                        i, box.class_id, double(box.confidence), box.x, box.y, box.width, box.height,
                        int(object.valid));
            if (object.valid)
                std::printf(" ice_ratio=%.9g\n", double(object.ice_ratio));
            else
                std::printf(" ice_ratio=unknown\n"); // 无效时库内为 -1，不按 0% 处理。
        }
        detector.release();
        return 0;
    } catch (const std::exception& error) {
        // Detector 析构会清理资源；此处处理示例读图、分配等异常。
        std::fprintf(stderr, "%s\n", error.what());
        return 2;
    }
}
```

最小示例只打印候选数量及筛选后的对象，不画框、不保存完整候选JSON；接口返回的 `snow_detections` 未被过滤或截断。完整留档使用第3节的demo。

最小示例退出码为：0=检测完成，1=接口调用失败，2=参数、样例读取等程序错误。

### 4.6 编译与运行

#### 链接预编译库

在SDK根目录执行，创建一个独立客户程序目录，不修改SDK内容：

```bash
sdk_dir="$PWD"
app_dir="$(mktemp -d /tmp/winch_ice_customer.XXXXXX)"
mkdir "$app_dir/bin"
cp demo/minimal.cpp "$app_dir/main.cpp"
cp -a lib "$app_dir/lib"
g++ -std=c++17 -O2 -I"$sdk_dir/include" "$app_dir/main.cpp" \
  -L"$app_dir/lib" -levs_ice -levs_core \
  -Wl,-rpath,'$ORIGIN/../lib' -o "$app_dir/bin/my_winch_app"
"$app_dir/bin/my_winch_app" "$sdk_dir/models/winch_model.rknn" "$sdk_dir/demo/sample.ppm"
```

以上命令只使用本包头文件和两个EVS库，已在RK3588验证。客户程序位于 `bin/`，配套库位于 `lib/`，运行时通过 `$ORIGIN/../lib` 查找；系统运行库仍由板端提供。

#### 编译完整留档demo

```bash
sdk_dir="$PWD"
cmake -S demo -B /tmp/winch_ice_demo_build -DEVS_SDK_ROOT="$sdk_dir"
cmake --build /tmp/winch_ice_demo_build -j2
```

产物为 `/tmp/winch_ice_demo_build/winch_ice_api_demo`。构建需要 `main.cpp` 和 `recording.cpp/h`，不能只编译main.cpp。

以上是板端原生编译方式。交叉编译需使用与目标板兼容的AArch64工具链，并在sysroot中准备配套的运行库和链接依赖。

## 5. 接口参考

所有检测类型位于 `evs::winch_ice`，头文件为 `evs/winch_ice.h`。`ErrorCode` 是 `uint32_t`，0表示成功，非0表示失败。日志接口是另外的可选接口，见第5.7节。

### 5.1 Detector的四个核心方法

#### initialize：初始化

```cpp
ErrorCode Detector::initialize(const WinchSnowConfig& config);
```

| 项目 | 说明 |
| --- | --- |
| 输入config | 完整功能配置，字段见第5.2节。模型路径和输入尺寸须与配套模型一致。库保存所需配置，调用返回后可释放外部配置对象。 |
| 输出参数 | 无。 |
| 返回值 | 0表示初始化成功；非0表示失败，库释放本次已取得的资源，可修正后重试。 |

初始化完成模型加载、张量检查、参数配置和可选预热。warmup=true时预热失败也使初始化失败。已初始化后重复调用直接返回0，保留原配置；新参数不会重新加载或校验。换模型、相机或输入规格，应先release再initialize。

常见错误：配置非法0x00084001、阈值越界0x00081003、能力不支持0x00081009、模型加载失败0x00082002、张量不匹配0x00082003、预热失败0x00083001、内存不足0x00081004。

#### detect：处理一帧

```cpp
ErrorCode Detector::detect(const ImageData& image, WinchSnowResult& result);
```

| 项目 | 说明 |
| --- | --- |
| 输入image | 当前原图，字段见第5.3节；紧凑RGB24或8位灰度，缓冲区保持到调用返回。 |
| 输出result | 本帧结果，字段见第5.4节；调用方可复用同一个结果对象。 |
| 返回值 | 0表示本帧调用正常，仍须判断结果有效性；非0时旧候选、对象和报警被清空，本帧业务结果不可用。 |

须先成功初始化。每次同步处理一帧，包括重复时间戳；错误后可以继续下一帧。没有自动报警锁存或停止检测。

返回码为0时，可读取snow_detections供影子系统使用，不要求result_code=1。业务结果再看result_code及objects[i].valid，只有valid=true才读取ice_ratio。低分候选、筛选后的卷扬框、面积估算有效的对象是不同阶段。没有卷扬框、无法估算面积、有效占比为0%是三种不同情况。

常见错误：未初始化0x00081007、空指针0x00081002、通道数错误0x00083002、尺寸错误0x00083003、推理失败0x00083001、张量或输出错误0x00082003、后处理失败0x00083005、NMS后业务对象超过两个0x00081003、内存不足0x00081004。

#### updateConfig：更新阈值

```cpp
ErrorCode Detector::updateConfig(const DetectConfig& config);
```

| 项目 | 说明 |
| --- | --- |
| 输入config | confidence_threshold、nms_threshold、area_ratio三个阈值整体更新。 |
| 输出参数 | 无。 |
| 返回值 | 0表示更新成功，后续detect使用新阈值；非0表示更新失败，原配置保留。 |

须先成功初始化。三个字段均须是[0,1]内有限数，NaN/Inf拒绝。不修改模型、输入尺寸和相机。建议复制当前DetectConfig后修改目标字段，成功后再保存宿主当前配置：

```cpp
auto next = config.detect_config;
next.area_ratio = 0.8f;
if (detector.updateConfig(next) == 0) config.detect_config = next;
```

常见错误：未初始化0x00081007、非法阈值0x00081003、内存不足0x00081004。

#### release：释放资源

```cpp
void Detector::release();
```

无输入、无输出参数、无返回值。释放内部任务和模型引用，不销毁外部Detector对象，也不释放调用方的图像和结果容器。允许重复调用；释放后可重新initialize，detect/updateConfig在重新初始化前返回未初始化。

构造后为未初始化状态；析构自动清理资源。Detector不可拷贝或移动。不要在检测未返回时并发release/析构。已经返回的结果由调用方持有，release不会自动清除宿主保存的旧结果。

### 5.2 配置字段

#### WinchSnowConfig

| 字段 | 类型 | 默认值 | 含义/范围 |
| --- | --- | --- | --- |
| model_config | ModelConfig | 见下表 | 模型配置。 |
| detect_config | DetectConfig | 见下表 | 检测阈值。 |
| camera_channel | uint32_t | 0 | 绑定相机的普通ID，0～254；不是多通道打包值。 |

#### ModelConfig

| 字段 | 类型 | 默认值 | 含义/范围 |
| --- | --- | --- | --- |
| Model_path | std::string | 空 | 有效模型文件路径，保留大写M。直接构造配置时，相对路径按进程工作目录解释。 |
| input_width | int32_t | 0 | 模型输入宽，像素；要求1～8192且与模型一致，本包填640。 |
| input_height | int32_t | 0 | 模型输入高，像素；同上，本包填640。 |
| warmup | bool | false | 是否初始化预热，true时预热失败也会使初始化失败。 |

#### DetectConfig

三个字段都是 `float`，必须是 [0,1] 内的有限数，不接受 NaN 或 Inf。

| 字段 | 默认值 | 判断规则 |
| --- | --- | --- |
| confidence_threshold | 0.45 | 置信度大于0且达到此值的卷扬框，才进入后续筛选；阈值为0时仍排除零分框。 |
| nms_threshold | 0.5 | 用NMS去掉重复框：两个框的IoU超过此值时，优先保留高分框。 |
| area_ratio | 0.5 | 任一valid=true的对象ice_ratio达到此值即报警；0.5表示50%。 |

IoU 是两个框的交集面积除以并集面积。三个配置项都不用于过滤 `snow_detections`，其中仍保留合法的低分、零分候选。

`detect`的返回结构不回传配置，demo另行保存当次配置用于留档。参数调整的影响见第7.3节，实际样例数值见第8.3节。

边界值：confidence_threshold=0仍排除零分业务框；=1时仅评分为1的框可通过。area_ratio=0时，只要有面积估算有效的对象，即使占比为0也满足报警条件。三个值均不是越高或越低就一定越好。

模型输入尺寸由配套模型决定，本包为640×640；相机原图尺寸在ImageData中另行传入。三个阈值不改变模型输入规格或HSV估算方法。

### 5.3 图像字段 ImageData

| 字段 | 类型 | 默认值 | 含义/范围 |
| --- | --- | --- | --- |
| data | const uint8_t* | nullptr | 原图首字节，非空、CPU可读。实际缓冲区至少width×height×channels字节。 |
| width | uint32_t | 0 | 原图像素宽，>0且≤INT_MAX/3；width×height≤INT_MAX。 |
| height | uint32_t | 0 | 原图像素高，>0且≤INT_MAX/2；还受总像素和设备内存限制。 |
| channels | uint32_t | 3 | 3=RGB24，R/G/B顺序；1=8位灰度。 |
| timestamp_ms | uint32_t | 0 | 毫秒标记，允许0、重复和自然回绕；库不据此去重或判断工况时效。 |

无stride/size_bytes字段。RGB每行width×3字节，灰度每行width字节，带行填充的图像先整理。BGR/NV12先转换成RGB。输入内存由宿主持有，至少保持到detect返回；库不保存图像指针。灰度复制成三通道后处理，其精度需单独验证。

### 5.4 输出结构体与枚举

#### WinchSnowResult

| 字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| result_code | ResultCode | RESULT_NO_RESULT | 临时表示卷扬检测状态：1至少一个通过筛选且置信度大于0的卷扬框，0没有；与HSV面积估算是否有效无关，不是API返回码。 |
| alert_level | AlertLevel | ALERT_NONE | 1表示有有效对象达到面积阈值，0表示本帧没有有效报警触发。接口失败时不据此判断安全状态。 |
| snow_detections | std::vector<Detection> | 空 | 临时返回卷扬模型合法候选；原图像素坐标、模型输出顺序，保留合法零分框，不做置信度过滤/NMS/Top-K，不限两个。像素宽高为0的框不入列。不是冰雪模型结果。 |
| inference_time_ms | uint32_t | 0 | 推理调用计时，四舍五入到毫秒，含后端调用/张量处理；不是纯NPU芯片时间或完整detect耗时。 |
| camera_channel | uint32_t | 0xFFFFFFFF | 本次绑定的普通相机ID；错误返回时不依赖该字段的特定值。 |
| objects | std::vector<WinchObjectResult> | 空 | 最多两个NMS后卷扬对象，按框中心从左到右排列，序号只对本帧有效。 |

#### WinchObjectResult

| 字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| box | Detection | 见下表 | 原图卷扬定位框。 |
| ice_ratio | float | -1 | valid=true时[0,1]，候选像素数/原图矩形框面积；无效时为-1。 |
| valid | bool | false | 当前对象的面积估算是否有效；false为未知，不能按0%处理。 |

无效对象不阻止其他有效对象触发报警。没有业务框时result_code=0，但snow_detections仍可能非空；已有卷扬框而全部无法估算面积时result_code=1、valid=false。结果没有稳定对象ID和对象级错误码。

#### Detection

| 字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| class_id | uint32_t | 0 | 本包单类卷扬ID为0。 |
| confidence | float | 0 | [0,1]，卷扬定位的目标概率×类别概率，不是冰雪占比。 |
| x | uint32_t | 0 | 原图框左上角x，像素。 |
| y | uint32_t | 0 | 原图框左上角y，像素。 |
| width | uint32_t | 0 | 框宽，像素；右边界=x+width。 |
| height | uint32_t | 0 | 框高，像素；下边界=y+height。 |

面积占比的分母为裁剪后原图框的width×height，不是卷筒表面分割面积。

| 枚举 | 底层类型 | 值 | 含义 |
| --- | --- | --- | --- |

### 5.7 可选日志接口

头文件：include/evs/alog.h；include/evs/alg_api.h仅转引此头。接口为C链接符号，实现在libevs_core.so.1。日志设置为进程全局，影响使用同一核心库的所有Detector。

#### 使用顺序

不接管日志时，可直接使用Detector。库首次构造内部Logger时安装默认桥，EVS日志输出到默认控制台；EVS_LOG_LEVEL和EVS_LOG_FILE影响默认Logger。

需要接入宿主日志时，在初始化Detector前注册回调，释放全部实例并停止库调用后再撤销：

```cpp
#include <evs/alg_api.h>
#include <cstdio>

static void receive_log(int level, const char* tag, const char* file,
                        int line, const char* msg) {
    std::fprintf(stderr, "[%d][%s][%s:%d] %s\n", level,
                 tag ? tag : "", file ? file : "", line, msg ? msg : "");
}

// 在现有程序中：
// alg_init(receive_log);
// initialize → detect / updateConfig → release全部实例
// alg_log_set_cb(nullptr);
```

完整可运行流程在demo/main.cpp中，运行命令：

```sh
./bin/winch_ice_api_demo configs/winch_ice.yaml demo/sample.ppm --log-callback --out /tmp/winch_log_run_01
```

注册宿主回调后，消息由宿主处理；默认Logger的文件输出、级别过滤和环形记录不再自动作用于这些消息。RKNN/OpenCV直接输出的内容不保证经过此回调；demo另外捕获标准输出/错误到run.log。

#### 函数输入和输出

| 函数 | 输入 | 输出/返回值 |
| --- | --- | --- |
| int alg_init(alg_log_cb log_cb) | 宿主回调地址；nullptr清空回调。 | 保存回调，当前实现固定返回0；只设置日志，不初始化模型或Detector。 |
| void alg_log_set_cb(alg_log_cb cb) | 新回调或nullptr。 | 直接替换全局回调，无输出参数和返回值。 |
| void alg_log_set_default_cb(alg_log_cb cb) | 默认回调或nullptr。 | 仅当前没有回调时赋值；已有回调保持不变；无返回值。一般供库内部使用。 |
| int alg_log_has_cb(void) | 无。 | 1=当前有回调（包括默认桥），0=没有。不能据此区分默认桥与宿主回调。 |
| void alg_log_emit(int level, const char* tag, const char* file, int line, const char* fmt, ...) | 级别、模块名、源文件、行号、printf格式及匹配的变参。 | 同步调用当前回调，无返回值；没有回调时直接返回。fmt须为有效非空格式串，变参类型必须匹配。 |

`alg_log_set_cb(nullptr)`只清空回调，不恢复默认桥。默认桥在内部Logger构造时安装一次；不要把撤销回调当成“恢复默认输出”。所有设置函数必须在停止库日志产生后串行调用，不能与detect、初始化或其他发日志的线程并发修改；本版全局回调指针没有并发保护。

#### 回调参数

```cpp
typedef void (*alg_log_cb)(int level, const char* tag,
                           const char* file, int line, const char* msg);
```

| 参数 | 含义和使用约定 |
| --- | --- |
| level | int，0=DEBUG、1=INFO、2=NOTICE、3=WARN、4=ERROR、5=FATAL；对应ALG_LOG_*常量。FATAL只是日志级别，接口本身不结束进程。 |
| tag | const char*，模块名；ALOG宏默认“algo”，可在包含头前定义ALG_MODULE。宿主读取时按可能为空处理。 |
| file | const char*，日志来源文件路径，可能包含编译目录；宿主可取文件名。按可能为空处理。 |
| line | int，来源行号。 |
| msg | const char*，已格式化消息；内部缓冲区1024字节，最多保留1023字节正文，超长截断。库不自动追加换行，格式串自身可包含换行。 |

回调无返回值，在发日志的线程内同步执行。三个字符串指针只在本次回调期间使用，异步入队须复制内容。回调保持简短，不抛异常，不在回调中调用ALOG/EVS日志或再次进入Detector，避免递归和重入。

#### ALOG宏

ALOG_DEBUG、ALOG_INFO、ALOG_NOTICE、ALOG_WARN、ALOG_ERROR、ALOG_FATAL均接收printf格式串和变参，自动填入级别、ALG_MODULE、__FILE__和__LINE__，无返回值。例如：

```cpp
#define ALG_MODULE "customer"
#include <evs/alog.h>
// 注册回调后：ALOG_INFO("frame=%u", frame_id);
```

EVS原Trace/Debug映射到DEBUG，Info映射到INFO，Warn映射到WARN，Error映射到ERROR。未注册回调时不格式化消息，但C/C++函数参数表达式仍会求值，不应在参数中放有副作用的操作。

### 5.8 版本与ABI

- 交付库的SONAME为 `libevs_core.so.1`、`libevs_ice.so.1`，使用同一批次的头文件、核心库和功能库。
- 公开接口包含C++标准库类型，不承诺任意工具链或跨版本C++ ABI兼容。更新库时，使用配套头文件重新编译客户程序。
- 本包版本、源码提交、模型及依赖校验值见 `VERSION.json`，文件完整性用 `SHA256SUMS` 核对。
- 调用方的C++对象构造、容器分配仍可能抛异常，应在程序边界处理；库不保证固定完成时间，也没有取消正在进行检测的接口。

## 6. 检测流程与结果映射

### 6.1 调用时序

```text
准备 WinchSnowConfig
  → initialize(config)
      失败：记录错误，修正配置后重试
      成功：进入检测
  → detect(image, result)
      返回非 0：本帧失败，不使用该帧业务结果
      返回 0：读取候选，再判断卷扬结果、对象 valid 和报警
  → 按需 updateConfig(完整 DetectConfig)
      成功：后续检测使用新阈值
      失败：继续使用原配置
  → 继续下一帧，或 release()
```

### 6.2 如何判断结果

先检查 `detect` 的返回码，再读业务字段。下面的 `valid` 和 `ice_ratio` 指 `objects` 中各个对象的字段。

| 情况 | 返回码 | result_code | 对象和面积占比 | alert_level |
| --- | --- | --- | --- | --- |
| 接口失败 | 非0 | 不用于业务判断 | 本帧业务输出不可用，不使用旧结果 | 不用于判断安全状态 |
| 没有筛选后的卷扬框 | 0 | 0 | objects为空；snow_detections仍可能非空 | 0 |
| 检出卷扬，但所有对象都无法估算面积 | 0 | 1 | 所有valid=false、ice_ratio=-1；占比未知 | 0，不表示无冰雪 |
| 至少一个对象面积估算有效，且没有对象达到面积阈值 | 0 | 1 | 有效对象valid=true、ice_ratio低于area_ratio | 0 |
| 任一有效对象达到面积阈值 | 0 | 1 | 该对象valid=true、ice_ratio≥area_ratio | 1 |

一个对象无效时，另一个有效对象仍可触发报警。有效占比为0%与无法估算面积不同；`area_ratio=0` 时，有效占比0%也会触发报警。`result_code` 和 `snow_detections` 当前仍暂按卷扬输出，不能据此认定已检测到冰雪目标。

### 6.3 候选与筛选结果的区别

```text
卷扬模型推理
  ├─ 合法候选 → snow_detections（不做置信度过滤、NMS或Top-K）
  └─ 置信度筛选 + NMS → objects（最多两个，否则本帧报错）
                           → HSV面积估算 → valid、ice_ratio、alert_level
```

`snow_detections` 中零分框保留，坐标为原图左上角和宽高，顺序沿用模型输出；像素宽高为0的框不入列。`objects` 只保留置信度大于0且达到阈值、经过NMS的卷扬框，按框中心从左到右排列。

因此，`result_code=0` 时仍可能有大量候选，不能用result_code决定是否读取snow_detections；先确认detect返回0即可。对象序号只对本帧有效，不能作为跨帧跟踪ID。

## 7. 任务配置YAML

### 7.1 配套配置

`winch_ice.yaml` 是demo使用的示例配置，直接构造WinchSnowConfig时可不使用：

```yaml
# Paths are relative to this YAML file, not the process working directory.
task: winch_ice
module_id: 0x0008
camera:
  video_channel: [0]
ground:
  enabled: false
Model_path: ../models/winch_model.rknn
input_width: 640
input_height: 640
warmup: false
confidence_threshold: 0.45
nms_threshold: 0.5
area_ratio: 0.5
```

- `Model_path` 保留大写M，示例指向SDK中的 `models/winch_model.rknn`。
- `load_config` 按YAML所在目录解释模型相对路径；直接构造ModelConfig时，相对路径按进程工作目录解释。
- 当前配置读取器不是通用YAML库。沿用本包结构，不要改成嵌套的 `model.path` 或 `model_config.Model_path`。
- 功能号固定为0x0008，后端、单类模型解码格式和HSV参数由本包实现固定。

### 7.2 哪些参数可以改

| 参数 | 修改方式 |
| --- | --- |
| confidence_threshold、nms_threshold、area_ratio | 可调整；运行中通过updateConfig整体更新三个字段 |
| Model_path、input_width、input_height、warmup、camera_channel | 初始化配置；修改时先release，再initialize |
| 模型解码格式、HSV的S/V阈值和形态学参数 | 当前公开接口不提供修改 |

修改YAML文件不会自动改变已初始化的实例；本包updateConfig接收DetectConfig结构体，不接收YAML路径。

### 7.3 三个阈值与输出评分

`confidence`是模型输出的评分，不是输入的`confidence_threshold`，也不等同于识别准确率。`ice_ratio`是输出的面积占比，`area_ratio`是输入的报警门槛。字段范围和默认值见第5节。

| 输入阈值 | 调高时 | 调低时 |
| --- | --- | --- |
| confidence_threshold | 排除更多低分框，也可能漏检 | 采用更多低分框，也可能引入错误框 |
| nms_threshold | 更容易保留重叠框 | 去重更严格，也可能排除相邻目标 |
| area_ratio | 更难触发报警 | 更容易触发报警 |

三个阈值都不用于过滤snow_detections。低分和零分候选保留，objects及报警结果按配置筛选。

HSV是色相H、饱和度S、亮度V。本包在卷扬框内按S≤80、V≥180及3×3开闭运算估算候选像素，不能把该占比理解成冰雪模型的置信度或真实卷筒表面分割面积。

## 8. 输出说明

### 8.1 文件用途

在SDK根目录调用`bin/winch_ice_api_demo`并成功处理样例后，会保存下列文件。中途失败时，只能查看失败前已生成的部分；版本快照另有生成条件，见表后说明。

| 文件 | 内容 |
| --- | --- |
| command.txt | 执行命令及工作目录 |
| config.yaml | 初始配置；updateConfig后的有效阈值看每帧JSON |
| sdk_version.json | 可执行文件所在目录的上一级存在VERSION.json时，复制为版本快照 |
| input.png | 未画框的输入图 |
| frame_000001.png | 筛选后的卷扬框、置信度和面积占比 |
| frame_000001.json | 本帧输入、实际配置、完整候选、对象、返回码和耗时 |
| result.json | 完整接口调用顺序、输入输出、退出状态及帧文件引用 |
| run.log | 完整demo接管的标准输出、标准错误、检测结果及日志 |
| annotated.png | 首帧画框图副本；本包附带的历史记录已去除这一重复图片 |

SDK内bin程序的上一级有VERSION.json，能生成版本快照。直接运行第4.6节在临时目录编译的完整demo时，上一级通常没有此文件，因此记录中可能没有sdk_version.json；这不影响检测，留档时仍应记录所用SDK版本。

多次检测时，后续帧按 `frame_000002` 等名称保存。绿色框表示低于面积阈值，红色框表示达到阈值，黄色或N/A表示无法估算面积。画框图不绘制全部原始候选，完整候选看JSON。

### 8.2 JSON字段与日志

| 文件 / 字段 | 含义 |
| --- | --- |
| frame JSON的input | 图像宽高、通道和timestamp_ms；data用input.png文件名表示，不记录内存地址 |
| frame JSON的config | 当次检测实际使用的配置，包含updateConfig成功后的新阈值 |
| frame JSON的return_code | detect返回码，0成功，非0失败 |
| frame JSON的elapsed_ms | 外部计量的完整detect调用耗时 |
| frame JSON的result | WinchSnowResult全部字段，含完整snow_detections和objects |
| result.json的calls | 每个已执行接口的输入、输出和耗时；非void接口还记录return_code/return_hex |
| release等void调用 | 无错误码；记录return_type=void及completed=true |
| result.json的frames | 各帧JSON和图片文件的引用，引用文件应配套保留 |
| result.json的exit_code / error | demo进程退出状态与错误说明 |

两个JSON都标明 `detections_target=winch` 和 `detections_stage=pre_confidence_pre_nms`。完整detect耗时与 `inference_time_ms` 不是同一指标。浮点配置序列化时，0.45可能显示为0.449999988，这是float表示差异。

完整demo把诊断和检测结果写入run.log，终端显示最终记录目录；最小示例直接把结果打印到终端。日志用于排障，客户程序应直接读取返回结构体。日志回调见第5.7节，RKNN/OpenCV直接输出的诊断不保证经过回调。

## 9. 部署与排障

### 9.1 部署布局与依赖

保留第2节的层级。已交付主demo的RUNPATH为 `$ORIGIN/../lib`，功能库的RUNPATH为 `$ORIGIN`，EVS两个库放在同一个lib目录。一般不需要额外设置LD_LIBRARY_PATH。

OpenCV的core/imgproc、RKNN及C/C++系统运行库由设备提供，即使客户程序未直接使用OpenCV也仍需部署兼容的运行库。运行依赖清单及校验值见VERSION.json。

### 9.2 自检

```bash
sha256sum -c SHA256SUMS
file bin/winch_ice_api_demo lib/libevs_core.so.1 lib/libevs_ice.so.1
ldd bin/winch_ice_api_demo
ls -l lib/libevs_core.so lib/libevs_ice.so
readelf -d bin/winch_ice_api_demo
readelf -d lib/libevs_ice.so.1
```

`file`应显示AArch64，`ldd`不应有not found，两个.so符号链接应指向相应.so.1。readelf查看声明的RUNPATH、SONAME及NEEDED；实际加载路径用ldd核对，确认两个EVS库来自本次部署目录。

### 9.3 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 启动提示找不到 libevs_*.so.1 | 保留 bin/、lib/层级及.so符号链接；用ldd确认加载本包库，两个EVS库须配套 |
| 找不到 librknnrt.so 或 libopencv_*.so.4.5d | 检查目标板运行库。本包依赖OpenCV core/imgproc及RKNN运行库，由设备提供；不要只因客户程序未使用OpenCV就省略运行库 |
| GLIBC_*、GLIBCXX_* 或 CXXABI_* 版本不满足 | 使用与目标板运行环境兼容的工具链或配套二进制；不能靠修改模型文件解决 |
| 0x00082002，模型加载失败 | 检查模型路径、读权限、文件校验值及RK3588目标匹配情况；结合RKNN日志排查 |
| 0x00084001 / 0x00084002，配置读取或解析失败 | 检查YAML路径、读权限及键值；load_config按YAML所在目录解析模型相对路径，直接构造配置则按工作目录解析 |
| 0x00081007，未初始化 | 先确认initialize返回0；release后须重新初始化 |
| 0x00081003，参数越界或对象数超限 | 初始化/更新时检查三个阈值是[0,1]有限数；detect时检查日志，筛选后超过两个对象也会返回此码，候选数组不会静默截成两个 |
| 图像数据、尺寸错误，或框和颜色异常 | 按ImageData约定检查缓冲区长度、RGB顺序和紧凑行布局；BGR/NV12及带行填充图像先转换、整理 |
| demo提示输出目录已存在 | 为--out指定一个新目录；不要覆盖已有运行记录 |
| demo读图失败 | 主demo只读P6/255 PPM；minimal.cpp只演示包内704×576样例。API本身接收内存缓冲区，不接收图片文件路径 |

### 9.4 接入前检查

- 使用配套模型、头文件和两个动态库，文件校验通过。
- 输入的RGB顺序、实际缓冲区长度和紧凑行布局正确。
- 图像内存在detect返回前有效，实例调用与释放串行。
- 返回码非0时按错误处理；valid=false时不使用ice_ratio作面积结论。
- 保留当前模型临时语义；候选输出不做置信度过滤。

## 10. 已知限制

- HSV按卷扬矩形框内的颜色估算冰雪候选面积，不是卷筒真实表面的分割结果。反光、背景、暗雪、透明冰和定位框偏差都会影响占比。
- 筛选后最多两个卷扬对象，超过两个时报错并清空本帧输出。此限制不用于截断snow_detections。
- 对象交叠、小于3×3的框、极暗或近均匀过曝图像等情况，可能返回valid=false、ice_ratio=-1，不能按0%处理。
- 系统运行库由目标设备提供，环境及依赖版本见VERSION.json。同为AArch64不代表任意发行版都能直接运行，部署前检查ldd。
- 当前没有冰雪模型；result_code和snow_detections暂按卷扬输出。HSV占比是颜色粗估，不能据此声称冰雪识别精度通过。
- 灰度输入会复制成三通道后处理，其颜色面积估算效果须单独验证。
- 没有稳定对象ID或对象级错误码，不提供多帧滤波、自动报警锁存或自动停止检测。
- 不承诺任意AArch64系统或跨版本C++ ABI兼容；本文验证范围为所列RK3588环境。
