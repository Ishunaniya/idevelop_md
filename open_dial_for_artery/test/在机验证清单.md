## 3. APN 重查 + 内存稳定性（**本次核心修复**，策略 1 或 2）

目的：通道切换时 `apn_obj_free()` 释放旧 APN 对象、下次拨号重新查询，且**长期不漏内存**。

### 3.1 切换后能重新拨上
设 `network_select=2`（PREFER_SIM，会在 SIM 失败时切 Roamlink、稳定后再切回）：

- [ ] 观察到一次 `SIM→Roamlink` 或 `Roamlink→SIM` 切换（日志关键字见下）
- [ ] 切换后再次出现 `net connected` / `Roamlink connected`（说明 APN 重查后拨号成功，未因释放对象导致空指针）
- [ ] `dmesg` / 日志**无** segfault、无 `dial` 异常退出被 `check_network.sh` 重启的记录

切换相关日志关键字：
```
policy=%d: SIM failed, switching to Roamlink
roamlink→SIM: reuse NW client / full init
policy=1: SIM fallback stable ... attempting Roamlink recovery
policy=2: Roamlink fallback stable ... attempting SIM recovery
Roamlink connected, entering active state
```

### 3.2 内存不随切换增长（直击泄漏）
泄漏量约每次切换 ~800B（+可能一个 deque），需多次切换放大：

- [ ] 记录初始 `VmRSS`：`grep VmRSS /proc/$PID/status`
- [ ] 让设备反复切换（策略 1/2 在主备稳定后每 ~300s 自动回切尝试；或人为拔插/屏蔽信号制造切换）
- [ ] 跑过 **≥20 次切换** 后再看 `VmRSS`
- [ ] **判据**：`VmRSS` 在小范围波动、不随切换次数单调上涨即通过；
      若每次切换稳定 +~1KB 持续累加，说明仍有泄漏，需复查

> 一行采样脚本（每 60s 记一次）：
> ```sh
> while :; do date +%s; grep VmRSS /proc/$(pidof dial)/status; sleep 60; done | tee /tmp/rss.log
> ```

### 3.3 快速制造切换（免等 300s 自动回切）

TCP 测试目标固定为 `18.196.0.17:22`（两条通道共用）。把到该 IP 的路由黑洞掉，
即可让 TCP 测试失败、逼出通道切换；这是把"20 次切换"压缩到几分钟内跑完的最快办法。

```sh
# 制造失败（屏蔽 TCP 测试目标）：
ip route add blackhole 18.196.0.17/32        # 或: iptables -A OUTPUT -d 18.196.0.17 -j DROP
# 恢复（让 TCP 测试重新通过，触发回切/恢复）：
ip route del blackhole 18.196.0.17/32        # 或: iptables -D OUTPUT -d 18.196.0.17 -j DROP
```

- SIM 通道：每 60s 测一次，连续 3 次失败（约 180s）后切换。
- Roamlink 通道：每 30s 测一次，连续 3 次失败（约 90s）后切换。
- 策略 1/2 下黑洞路由会让两条通道都失败 → **持续 flip-flop**，正好密集触发
  `apn_obj_free` 路径，配合 §3.2 的 VmRSS 采样最有效。验证完务必 `ip route del` 恢复。
- 另一种更贴近现网的方式：拔天线 / 进电梯 / `AT+CFUN=0` 制造注册丢失，验证 reg 超时切换。

> 注意：黑洞路由只影响 TCP 测试连通性，真实数据面可能仍通——这正是"测试目标不可达"
> 的模拟场景，符合预期。

仅当 `apn.json` 中该 ICCID 的 `is_oper_select=true` 才会走 `list_oper`/`select_oper`：

- [ ] 触发 `wait_for_connect` 超时（60s 拨不上）后进入 `list_oper`

> 若现网该卡 `is_oper_select=false`（默认多为此），本节可跳过，仅记录"未走此路径"。
