# 复盘模板

## 事实

- 哪份产物最早发现了需求歧义？
- 哪项规格未被 tasks 覆盖？
- 哪项评审结论改变了实现或验证？

## 成本与收益

- 本任务的计划、澄清、验证、评审分别花了多少时间？
- 相比直接提示 AI 修改代码，留下了哪些可复用资产？
- 哪些环节对小改动过重，应改为按风险触发？

## 团队决定（填写）

- [ ] 仅把“分析阶段不得修改代码”固化到仓库指令。
- [ ] 对跨模块/高风险改动试用 OpenSpec。
- [ ] 对需求不明确的改动使用 CONTEXT + ADR。
- [ ] 先评估 Unity/Ceedling 与硬件 mock，再要求嵌入式 C 使用 TDD。
- [ ] 暂不接入，待下一次真实变更复评。
