要特别更正一种容易造成误判的说法：**Pointsheet-3 的点名不是过期名单**。它的 179 个 name 与 2026-06-30 包中的 Pointsheet_info1.json 一致。真正需要关注的是字段属性、类型和脚本输出，而不是简单地把整张 Pointsheet-3 判为陈旧。

旧版 Pointsheet.xlsx 有 157 个点名：其中 2 个表内有、当前 JSON 无；当前 JSON 有 24 个点名、旧表缺失，包括新增的金科字段等。因此它不能单独作为当前交付点表输入。

### 5.2 影响生成结果的差异

- Pointsheet-3 与 2026-06-30 JSON 的 179 个点名一致，比例系数也一致；但 **38 个点的 upload_diff 不一致**。这些行在工作簿中 upload_diff=1 且 multiply<1，例子包括 RSV11、RSV10、RSV9、RSV6、Nu0001。当前 JSON 中没有 scale<1 且 udif=1 的点。EC200A 2026-04-07、2026-06-08/09 README 明确记载：scale 小于 1 时，udif 从 1 改为对应 scale，以免小幅工况变化漏报。因此当前 JSON 与该规则一致，Pointsheet-3 的相关值可能未同步；在找到受控输入版本前，不能按这张表盲目重生成。

## 13. 最终结论

本次复核确认交接资料中有可用的协议、点表和固件线索，也发现了若干需要在接手阶段明确处理的版本差异、安全风险和验证缺口。最关键的事实是：Pointsheet-3 的点名与当前 JSON 一致，但其 38 个 upload_diff 以及部分生成器元数据并不一致；因此不应把“点名匹配”误当成“可以直接重生成并交付”。

**交接可以继续推进，但在凭证处置、点表规则对齐、协议定稿和实车/端到端验证完成前，不建议把现有资料认定为完整验收包或直接据此发布新固件。**

本报告只保留核验结论与安全必要的证据定位，未复述凭证、设备号码或口令明文。
