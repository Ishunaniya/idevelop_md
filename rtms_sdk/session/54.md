## Bug 1【严重】EG25：PREFER_ROAMLINK / FORCE_ROAMLINK 启动时 Roamlink 永不激活

### 问题描述

EC200A `dial_loop()` 在进入主巡检循环前，有明确的启动初始化块（`dialer_ec200a.cpp:1034-1049`），策略1/3 时会直接启动 RBMaster + Roamlink 服务，将 `is_roamlink_active` 置 true。

EG25 `dial_task()` 没有对应代码。`dial_mng_new()` 初始化时 `is_roamlink_active = false`，进入主循环后直接走 SIM 拨号状态机，Roamlink 从未被启动过。

### 实际运行后果

- 配置 PREFER_ROAMLINK（策略1）：设备启动后完全走 SIM 通道，与策略名称相反，只有 SIM 断网超 3 分钟才会触发切换，不会主动从 Roamlink 开始。
- 配置 FORCE_ROAMLINK（策略3）：因为 `is_roamlink_active` 永远为 false，守护块（`if (is_roamlink_active)`）永远不进，Roamlink 完全无法激活。

### 修复位置

**`eg25/dial/dial.c`，`dial_task()` 函数内，`printf("begin dial \n")` 之前（原 462 行附近），新增：**

```c
/* 策略1/3（优先/强制 Roamlink）：启动时直接激活 Roamlink 通道（对齐 EC200A 行为） */
if (p_dial_mng->roamlink_available &&
    (p_dial_mng->network_policy == NET_POLICY_PREFER_ROAMLINK ||
     p_dial_mng->network_policy == NET_POLICY_FORCE_ROAMLINK)) {
    dial_log("[ROAMLINK] Policy requires Roamlink as initial channel. Starting RBMaster...\n");
    roamlink_eg25_start_master();
    if (roamlink_eg25_start_service(p_dial_mng->smd_fd)) {
        p_dial_mng->is_roamlink_active    = true;
        p_dial_mng->roamlink_start_ts     = time(NULL);
        p_dial_mng->roamlink_last_ping_ts = 0;
        dial_log("[ROAMLINK] Initial channel: Roamlink (virtual SIM)\n");
    } else {
        dial_log("[ROAMLINK] Initial start failed, falling back to SIM\n");
    }
}
```

**设计说明：**
- 与 EC200A 对齐：两平台策略1/3 均在启动时激活 Roamlink。
- EG25 启动失败时 `is_roamlink_active` 保持 false（不强制标记），因为 EG25 的守护块在 `is_roamlink_active=false` 时不做重试，而是让 SIM 通道先跑，等 SIM 断网后再由切换逻辑接管。（EC200A 的处理不同，见 Bug 3。）
- 策略4（FORCE_SIM）和策略2（PREFER_SIM）不受影响，条件不满足，不进此块。

## Bug 2【严重】EG25：FORCE_ROAMLINK 的 SIM→Roamlink 切换条件缺失

### 问题描述

`eg25/dial/dial.c` 心跳块内的 SIM→Roamlink 切换条件（修复前）：

```c
if (!net_ok && start_fail_ts > 0 && !p_dial_mng->is_roamlink_active &&
    p_dial_mng->roamlink_available &&
    (p_dial_mng->network_policy == NET_POLICY_PREFER_SIM ||
     p_dial_mng->network_policy == NET_POLICY_PREFER_ROAMLINK) &&   // ← 漏掉 FORCE_ROAMLINK
    downtime_sec >= ROAMLINK_SWITCH_TIMEOUT_SEC) {
```

`NET_POLICY_FORCE_ROAMLINK` 不在列表中。

### 实际运行后果

即使 Bug 1 修完（启动时 start_service 成功），如果 Roamlink 后续失败、守护块切回 SIM（PREFER_ROAMLINK 策略走守护），那切换条件能正常工作。但对于 FORCE_ROAMLINK：守护块不切 SIM（守护块有 else 分支重启服务），所以守护切回 SIM 后理论上不走切换条件。但若 Bug 1 的启动失败 fallback 导致 `is_roamlink_active=false`，切换条件就是 FORCE_ROAMLINK 重新激活的唯一路径，而此条件不包含 FORCE_ROAMLINK，导致永久停在 SIM。

### 修复位置

**`eg25/dial/dial.c`，切换条件（修复后 630 行附近），加入策略3：**

```c
if (!net_ok && start_fail_ts > 0 && !p_dial_mng->is_roamlink_active &&
```

## Bug 3【中等】EC200A：FORCE_ROAMLINK 启动失败后无任何恢复路径

### 问题描述

修复前的 EC200A 启动块（`dialer_ec200a.cpp:1034-1044`）：

```cpp
if (roamlink_ec200a_start_service()) {
    is_roamlink_active = true;     // ← 仅在成功时设置
    roamlink_start_ts = now_ms();
    dial_log("[ROAMLINK] Initial channel: Roamlink (virtual SIM)\n");
}
// start_service 失败时：is_roamlink_active = false，roamlink_start_ts = 0
```

若 `roamlink_ec200a_start_service()` 在启动时返回失败：
- `is_roamlink_active = false` → 守护块 `if (is_roamlink_active)` 永远不进
- ping 失败切换条件（`:1394-1396`）只包含 PREFER_SIM / PREFER_ROAMLINK，不包含 FORCE_ROAMLINK
- 结果：FORCE_ROAMLINK 策略下，Roamlink 启动一次失败后永久停在 SIM，无自愈

### 修复位置

**`dialer_ec200a.cpp`，启动块（1034-1049 行），将 `is_roamlink_active` 和 `roamlink_start_ts` 移到 `if/else` 外：**

```cpp
if (roamlink_available &&
    (network_policy == NET_POLICY_PREFER_ROAMLINK || network_policy == NET_POLICY_FORCE_ROAMLINK)) {
    dial_log("[ROAMLINK] Policy requires Roamlink as initial channel. Starting RBMaster...\n");
    roamlink_ec200a_start_master();
    if (roamlink_ec200a_start_service()) {
        dial_log("[ROAMLINK] Initial channel: Roamlink (virtual SIM)\n");
    } else {
        dial_log("[ROAMLINK] Initial start failed, guard will retry in %ds\n",
                 (int)(ROAMLINK_CONNECT_TIMEOUT_MS / 1000));
    }
    /* 无论启动成功或失败，均标记 active + 记录时间戳，
     * 让守护块负责后续超时重试（FORCE_ROAMLINK）或切回SIM（PREFER_ROAMLINK）*/
    is_roamlink_active = true;
    roamlink_start_ts  = now_ms();
}
```

**设计说明：**
- 无论 start_service 成功或失败，都将 `is_roamlink_active = true` + 记录启动时间戳。
- 守护块会在 `ROAMLINK_CONNECT_TIMEOUT_MS`（300秒）后检测到 `roamlink_last_ping_ts == 0`（从未 ping 通），触发超时：
  - FORCE_ROAMLINK：重启服务（else 分支），循环重试
  - PREFER_ROAMLINK：切回 SIM（if 分支），设 `sim_fallback_ts`，300s 后再尝试回切
- 这是利用已有守护机制做自愈，不需要新增代码。

## Bug 4【中等】两平台：所有通道切换点 `ping_fail_count` 未清零

### 问题描述

`ping_fail_count` 是 jitter 过滤器，连续失败达到 `PING_FAIL_THRESHOLD=3` 才触发故障计时器 `start_fail_ts`。

切换通道（SIM→Roamlink 或 Roamlink→SIM）时，每个切换点都会重置 `start_fail_ts = 0`，但没有重置 `ping_fail_count`。

**实际运行后果（场景还原）：**

1. 当前在 Roamlink，ping 连续失败 3 次，`ping_fail_count = 3`
2. 守护块触发（300s timeout）→ 切换到 SIM，`start_fail_ts = 0`，`ping_fail_count` 仍为 3
3. SIM 第 1 次 ping 失败：`ping_fail_count = 4`，已 >= 3，跳过抖动过滤
4. `start_fail_ts == 0` → 立即设 `start_fail_ts = tnow`，3 分钟倒计时从第 1 次 ping 失败就开始
5. SIM 如果需要 3 分钟以上才能建立连接（例如注册慢），3 分钟一到就再切回 Roamlink
6. 产生不必要的快速乒乓切换

正常应有的行为：切换后，新通道的第 1-3 次 ping 失败属于连接建立期的正常现象，应被抖动过滤器吸收。

### 修复位置

所有通道切换成功路径均加 `ping_fail_count = 0`，共 8 处：

#### EC200A（`dialer_ec200a.cpp`）

| 切换动作 | 行号（修复后） | 修改内容 |
|---------|--------------|---------|
| 守护块：Roamlink 超时 → SIM | ~1128 | `ping_fail_count = 0` 加在 `start_fail_ts = 0` 之后 |
| 策略1回切：SIM → Roamlink（成功路径） | ~1349 | `ping_fail_count = 0` 加在 `start_fail_ts = 0` 之后 |
| 策略2回切：Roamlink → SIM | ~1367 | `ping_fail_count = 0` 加在 `sleep(2)` 之前 |
| ping失败切换：SIM → Roamlink（成功路径） | ~1418 | `ping_fail_count = 0` 加在 `start_fail_ts = 0` 之后 |

#### EG25（`eg25/dial/dial.c`）

| 切换动作 | 行号（修复后） | 修改内容 |
|---------|--------------|---------|
| 守护块：Roamlink 超时 → SIM（策略1/2） | ~604 | `ping_fail_count = 0` 加在 `start_fail_ts = 0` 之后 |
| ping失败切换：SIM → Roamlink（成功路径） | ~642 | `ping_fail_count = 0` 加在 `start_fail_ts = 0` 之后 |
| 策略1回切：SIM → Roamlink（成功路径） | ~536 | `ping_fail_count = 0` 加在 `start_fail_ts = 0` 之后 |
| 策略2回切：Roamlink → SIM | ~556 | `ping_fail_count = 0` 加在 `dail_start_data_call` 之前 |

**注意：** 切换失败路径（`else` 分支，start_service 调用失败）不加，因为此时通道并未实际切换，旧计数仍有意义。

### Bug 5【轻微】EC200A：主循环内 `sleep()` 阻塞 watchdog 更新

4处 sleep 在 `ST_PING` case 内部：
- `:1128` `sleep(5)` — 策略3守护重启服务
- `:1335` `sleep(2)` — 策略1回切停SIM后等待
- `:1360` `sleep(2)` — 策略2回切停Roamlink后等待
- `:1401` `sleep(2)` — ping失败切换停SIM后等待

`cpactive_upt_atime(cpactive)` 在循环顶部，sleep 期间不调用。当前 `timeout=60s`（`main()` 中设置），最长 sleep 5s，在安全范围内。如将来 watchdog 收紧到 <5s 需改为异步方式，暂不处理。
