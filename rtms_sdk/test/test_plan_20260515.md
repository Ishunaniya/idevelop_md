## 测试环境准备

### 文件路径速查

| 路径 | 含义 |
|---|---|
| `/usrdata/network.ini` | 策略配置（1~4） |
| `/usrdata/roamlink/RBMaster` | Roamlink 服务主程序 |
| `/usrdata/roamlink/etc/.pconfig/license.cer` | License 文件 |
| `/data/ufs/license.cer` | License 备份 |
| `/opt/conf.ini` | Roamlink 配置（factoryApp 下载） |
| `/tmp/dial_Status` | 结构化状态输出 |
| `/tmp/dial_retry_count` | 快速失败重启计数 |
| `/tmp/cfun_count.txt` | CFUN 调用次数（EC200A） |
| `/tmp/cfun_last_call.txt` | 上次 CFUN 调用时间（EC200A） |
| `/tmp/network_type` | 当前通道标记（SIM/ROAMLINK） |

### 策略配置写法

```ini
# /usrdata/network.ini
[network]
network_select=1   # 1=PREFER_ROAMLINK, 2=PREFER_SIM, 3=FORCE_ROAMLINK, 4=FORCE_SIM
```

### 状态观测命令

```bash
# 实时查看日志（EC200A）
tail -f /media/sdcard/dial_log/dial_*.log

# 查看结构化状态
cat /tmp/dial_Status

# 查看当前通道
cat /tmp/network_type

# 查看 RBMaster 是否在运行
ps aux | grep RBMaster

# 查看 Roamlink 控制端口
nc -z 127.0.0.1 5568 && echo "port OK" || echo "port CLOSED"
```

## 二、Roamlink 模块基础功能（EC200A）

### 2.1 Probe 四种情况

#### TC-R01：RBMaster 不存在 → PROBE_NO_PACKAGE
- 前提：移除或重命名 `/usrdata/roamlink/RBMaster`
- 预期：启动日志输出 `probe NO_PACKAGE`，`network_policy` 强制为 4（FORCE_SIM），`/tmp/network_type = SIM`
- 验证：`cat /tmp/dial_Status | grep policy` 显示 4

#### TC-R02：conf.ini 不存在 → PROBE_CONF_MISSING
- 前提：RBMaster 存在，移除 `/opt/conf.ini`
- 预期：日志 `probe CONF_MISSING`，强制 FORCE_SIM

#### TC-R03：license 存在且有效 → PROBE_OK
- 前提：RBMaster、conf.ini、license.cer 均就绪，`network_select=1`
- 预期：日志 `probe OK, roamlink available`，`/tmp/network_type = ROAMLINK`（启动时切入）

#### TC-R04：license 缺失，备份存在 → 自动恢复
- 前提：删除 `/usrdata/roamlink/etc/.pconfig/license.cer`，保留 `/data/ufs/license.cer`
- 预期：日志 `license restored from backup`，re-probe 成功，`roamlink available`，进入 Roamlink 通道

#### TC-R04b：备份恢复成功但 re-probe 仍失败
- 前提：删除 license，保留备份；在备份复制期间同时删除 `/opt/conf.ini`（模拟并发文件缺失）
- 代码路径：`restore_from_backup()` 返回 true → re-probe 返回 `CONF_MISSING` → 强制 FORCE_SIM
- 预期：日志 `backup restore succeeded but re-probe failed`，`roamlink_available=false`，`policy=4`
- 验证：`cat /tmp/dial_Status | grep roamlink_available` 显示 0，SIM 正常联网

#### TC-R05：license 缺失，备份也不存在 → license_pending 模式（policy=1）
- 前提：删除 license 和备份，`network_select=1`
- 预期：
  - 日志 `license_pending mode, force SIM until license downloaded`
  - `cat /tmp/dial_Status | grep license_pending` = 1
  - 物理 SIM 正常联网（FORCE_SIM 临时生效）
  - SIM 首次 ping 通后，RBMaster 被启动（日志 `starting RBMaster for license download`）
  - 放入真实 license 文件后，60s 内日志 `license file appeared! backing up and rebooting`，设备重启

#### TC-R05b：license 缺失，备份不存在 → license_pending 模式（policy=2）
- 前提：删除 license 和备份，`network_select=2`（PREFER_SIM）
- 代码路径与 TC-R05 相同（license_pending 分支不依赖 policy 值）
- 预期：
  - 同 TC-R05：`license_pending=1`，FORCE_SIM 临时生效，SIM 联网后启动 RBMaster 下载 license
  - 区别：本用例确认 PREFER_SIM 策略下该分支行为与 PREFER_ROAMLINK 一致
- 验证：`cat /tmp/dial_Status` 中 `policy=4`（被覆盖）、`license_pending=1`

#### TC-R05c：license_pending 300s 超时 → 放弃，保持 FORCE_SIM 继续运行（不重启）
- 前提：删除 license 和备份，`network_select=1`，SIM 联网后 **不放入** license 文件
- 代码路径：`wait_elapsed > LICENSE_WAIT_TIMEOUT_SEC(300s)` → `license_pending = false`，进程继续以 FORCE_SIM 运行
- 预期：
  - 300s 内每 60s 日志 `license check (XXs / 300s elapsed)...` + `license not yet available`
  - 300s 后日志 `license wait timeout (XXs), giving up license_pending mode, stay FORCE_SIM`
  - **设备不重启**，继续以物理 SIM 联网运行
- 验证：`cat /tmp/dial_Status | grep license_pending` 变为 0，`channel=SIM`，网络保持可用

#### TC-R05d：license_pending 模式下 SIM 断线重连，RBMaster 不重复启动
- 前提：TC-R05 场景（license_pending 激活，RBMaster 已启动一次）
- 操作：SIM 联网后短暂断网（模拟信号波动），再重新联网
- 代码路径：`has_notified_connect` 重置后再次进入 `wait_for_connect` → `rbmaster_started=true` 阻止再次 fork
- 预期：**不出现**日志 `starting RBMaster for license download` 第二次，RBMaster 进程数量不变
- 验证：`ps aux | grep RBMaster | wc -l` 始终为 1

### 2.2 RBMaster 进程管理

#### TC-R06：`is_master_running` 双重检测
- 启动 RBMaster 后验证端口 5568 可连通，`is_master_running` 返回 true
- 用 `kill -9` 杀掉 RBMaster 进程但不清理 PID 文件，验证：端口关闭后 `is_master_running` 返回 false（僵尸进程检测有效）

#### TC-R07：start_master 双重 fork 无僵尸
- 调用 `start_master` 后，用 `ps aux | grep Z` 验证无僵尸进程产生

#### TC-R08：重复调用 `start_master` 不重复启动
- RBMaster 已运行时，日志应出现 `RBMaster already running, skip`

#### TC-R08b：启动时清理残留 RBMaster（策略为 PREFER_SIM / FORCE_SIM）
- 前提：手动启动 RBMaster（`/usrdata/roamlink/RBMaster &`），确认端口 5568 可达，再重启 `modem_mng` 且 `network_select=2` 或 `=4`
- 代码路径：`dial_mng_new` 中检测到 `is_master_running()=true` + policy 属于 PREFER_SIM/FORCE_SIM → 调用 `roamlink_stop_service()` + sleep(2)
- 预期：日志 `stopping residual RBMaster service`，2s 后 `ps aux | grep RBMaster` 无输出，SIM 拨号正常
- 验证：`/tmp/network_type = SIM`，无 Roamlink 切换行为

### 2.3 策略配置读取

#### TC-R09：`/usrdata/network.ini` 读取正常
- 分别写入 1/2/3/4，重启 `modem_mng`，验证 `cat /tmp/dial_Status | grep policy_name` 分别为 PREFER_ROAMLINK / PREFER_SIM / FORCE_ROAMLINK / FORCE_SIM

#### TC-R10：`/usrdata/network.ini` 不存在时默认策略
- 删除配置文件，验证日志 `not found, use default policy 4`，以 FORCE_SIM 运行

#### TC-R11：`network.ini` 中值越界时回退默认
- 写入 `network_select=5` 或 `network_select=0`，验证日志 `invalid policy`，回退到 4

### 2.4 无 Roamlink 设备 + 激进策略（probe 强制覆盖 policy）

#### TC-NR01：`network_select=1`（PREFER_ROAMLINK）+ RBMaster 不存在
- 前提：移除 `/usrdata/roamlink/RBMaster`，`network_select=1`
- 代码路径：probe 返回 NO_PACKAGE → `network_policy` 强制覆盖为 4（FORCE_SIM），`roamlink_available=false`
- 预期：日志 `probe NO_PACKAGE: RBMaster missing, force SIM`，启动后走 SIM 拨号，L1/L2/L3 正常生效
- 验证：`cat /tmp/dial_Status` 中 `policy=4`、`roamlink_available=0`、`channel=SIM`；断网 3min 后不切 Roamlink

#### TC-NR02：`network_select=3`（FORCE_ROAMLINK）+ RBMaster 不存在
- 前提：移除 RBMaster，`network_select=3`
- 预期：同 TC-NR01，probe 覆盖为 FORCE_SIM，SIM 正常联网，永不触发 Roamlink 切换
- 验证：`cat /tmp/dial_Status` 中 `policy=4`；`/tmp/network_type = SIM` 始终不变

#### TC-NR03：`network_select=1`（PREFER_ROAMLINK）+ conf.ini 缺失
- 前提：RBMaster 存在，移除 `/opt/conf.ini`，`network_select=1`
- 代码路径：probe 返回 CONF_MISSING → `network_policy` 强制覆盖为 4
- 预期：日志 `probe CONF_MISSING`，行为同 TC-NR01（纯 SIM + L1/L2/L3）
- 验证：`policy=4`、`roamlink_available=0`

## 三、Roamlink 四种策略切换（EC200A + EG25）

### 策略1：PREFER_ROAMLINK（`network_select=1`）

#### TC-P1-01：启动时进入 Roamlink 通道
- 预期：日志 `Initial channel: Roamlink`，`/tmp/network_type = ROAMLINK`，能正常 ping 通

#### TC-P1-02：Roamlink 启动后 300s 内未 ping 通 → 切 SIM
- 操作：启动后立即停止 RBMaster（`killall RBMaster`），等待 300s
- 预期：日志 `[ROAMLINK] Connect timeout (300s), switching to SIM`，切到物理 SIM 联网
- 验证：`/tmp/network_type = SIM`，`ping 8.8.8.8` 通；期间 `roamlink_state=starting` → 切换后 `roamlink_state=none`

#### TC-P1-03：Roamlink ping 通后断线 300s → 切 SIM
- 操作：Roamlink 运行正常后，手动停止 RBMaster，等待 300s
- 预期：日志 `[ROAMLINK] Channel fail timeout (300s), switching to SIM`，切 SIM

#### TC-P1-04：SIM 备用稳定 300s → 回切 Roamlink
- 前提：TC-P1-02 或 TC-P1-03 后，SIM 通道稳定联网
- 等待 300s，预期：日志 `Policy1: SIM stable XXs, trying Roamlink recovery`，回切 Roamlink
- 验证：`/tmp/network_type = ROAMLINK`

#### TC-P1-05：回切 Roamlink 失败 → 重置计时继续等待
- Roamlink 回切时 RBMaster 启动失败，预期：`roamlink_fail_count++`，`sim_fallback_ts` 重置，300s 后再次尝试

### 策略2：PREFER_SIM（`network_select=2`）

#### TC-P2-01：启动时走物理 SIM
- 预期：`/tmp/network_type = SIM`，物理 SIM 正常联网

#### TC-P2-02：SIM 断网 3 分钟 → 切 Roamlink（成功）
- 操作：拔出 SIM 卡（或关闭 SIM），等待 3 分钟
- 预期：日志 `policy=2: SIM down XXs, switching to Roamlink`，切入 Roamlink
- 验证：`/tmp/network_type = ROAMLINK`，网络恢复

#### TC-P2-02b：SIM 断网 3 分钟 → 切 Roamlink 失败 → 重置计时再重试
- 前提：`network_select=2`，RBMaster 存在但故意让 `roamlink_start_service()` 失败（如阻断端口 5568）
- 代码路径：`roamlink_start_service()` 返回 false → `roamlink_fail_count++`、`start_fail_ts = tnow`（重置）→ 3min 后再次触发切换
- 预期：
  - 日志 `[ROAMLINK] Switch failed`
  - **不切换到 Roamlink 通道**（`is_roamlink_active` 保持 false）
  - 3min 后再次出现日志 `policy=2: SIM down XXs, switching to Roamlink`
- 验证：`/tmp/network_type = SIM`（切换失败期间），`roamlink_fail_count` 递增

#### TC-P2-03：Roamlink 备用稳定 300s → 回切 SIM
- 前提：SIM 恢复后，在 Roamlink 备用通道等待 300s
- 预期：日志 `Policy2: Roamlink stable XXs, trying SIM recovery`

### 策略3：FORCE_ROAMLINK（`network_select=3`）

#### TC-P3-01：启动时强制 Roamlink，从不切 SIM
- 停止 RBMaster，等待 300s 超时
- 预期：日志 `[ROAMLINK] FORCE_ROAMLINK: connect timeout, restarting service`，**不切 SIM**，继续重启 Roamlink；状态文件 `roamlink_state=starting` 保持不变
- 验证：`/tmp/network_type = ROAMLINK` 始终不变

#### TC-P3-02：Roamlink 重启后重新连通
- 在 FORCE_ROAMLINK 重启期间，重新启动 RBMaster
- 预期：重启后 ping 恢复，日志正常心跳

### 策略4：FORCE_SIM（`network_select=4`）

#### TC-P4-01：强制物理 SIM，Roamlink available 时也不切换
- 前提：Roamlink 配置完整，`network_select=4`，SIM 断网 > 3min
- 预期：**不切 Roamlink**，L1/L2/L3 恢复机制生效
- 验证：`/tmp/network_type = SIM` 始终不变

## 四、L1/L2/L3 分级恢复

### EC200A（策略4，阈值 5/10/35min）

#### TC-L1-01：L1 软重拨（5min）
- 前提：`network_select=4`，`has_connected_once=1`，断网超过 5min，REG 状态正常（非 0）
- 预期：日志 `Trigger Level 1 recovery`，`ql_data_call_stop + ql_data_call_start` 执行
- 验证：重拨后若 SIM 恢复，`start_fail_ts` 清零，`last_l1_ts` 更新

#### TC-L1-02：L1 不在 REG=0 时执行
- REG 状态为 0（未注册），断网超过 5min
- 预期：L1 被跳过（等待 L2）

#### TC-L2-01：L2 CFUN 重置（10min）
- 断网超过 10min，或 REG=0 超过 1.5min
- 预期：日志 `Trigger Level 2 recovery`，`AT+CFUN=0 / AT+CFUN=1` 执行
- 验证：`last_l2_ts` 更新，L2 冷却生效（5min 内不重复触发）

#### TC-L2-02：REG=0 时 L2 加速触发（L2 冷却 90s）
- 网络未注册（REG=0），断网超过 5min
- 预期：L2 在 `last_l2_ts + 90s` 后触发，比正常路径（5min）更快

#### TC-L3-01：L3 硬重启（35min）
- 断网超过 35min
- 预期：日志 `FATAL: Network down 35mins. Sending AT+CFUN=1,1 then exit.`，进程退出，等待 watchdog 重启

#### TC-L3-02：`has_connected_once` 保护启动期
- 新启动进程，从未 ping 通，等待 6min
- 预期：L1 **不触发**（`has_connected_once=0`）
- 首次 ping 成功后，再断网 5min → L1 正常触发

### EG25（策略4，阈值 60s/5min/30min）

#### TC-EG25-L1-01：L1 软重拨（60s）
- EG25 平台，断网 60s，REG 正常
- 预期：`dail_stop_data_call + dail_start_data_call`，日志 recovery_level=1

#### TC-EG25-L2-01：L2 CFUN 重置（5min）
- 断网 5min
- 预期：`AT+CFUN=0 → AT+CFUN=1`，`last_recovery_ts` 更新

#### TC-EG25-L2-02：`last_recovery_ts` 清零验证（bug 修复）
- 流程：断网 → L2 触发 → 网络恢复 → 再次断网
- 预期：第二次断网满 5min 后才触发 L2（不提前）
- 反例：修复前，第二次断网可能仅 3.7min 就触发

#### TC-EG25-L3-01：L3 进程退出（30min）
- 前提：EG25 平台，`network_select=4`，`has_connected_once=1`，断网超过 30min
- 预期：日志 `FATAL: Network down 30mins`，进程退出（exit 或 CFUN 硬重启），等待 watchdog 重新拉起
- 验证：`echo 3 > /tmp/dial_retry_count` 后启动（持久模式），断网计时器跑满 30min 触发

#### TC-EG25-HC-01：EG25 启动时网络已连通，`has_connected_once` 直接置 1
- 前提：modem_mng 启动前 PDP 已建立且 ping 可通（如上次进程被 kill 后快速重启）
- 预期：进程在 `dial.c` line 523 附近直接将 `has_connected_once=1`，日志显示跳过初始等待
- 验证：启动后立即断网 60s → **L1 正常触发**（因为 `has_connected_once` 已为 1，不被守卫拦截）
- 对比：全新启动时断网 60s → L1 **不触发**（`has_connected_once=0`）

## 六、SIM 卡 SDK 回调（EC200A）

### TC-SIM-01：回调注册成功，心跳显示 SIM_CB 值
- 启动后检查心跳日志格式：
  ```
  [HEARTBEAT] SIM_AT:READY | SIM_CB:READY | REG:1 | CSQ:22 | TEMP:45 | DownTime:0s
  ```
- SIM_AT 和 SIM_CB 均为 `READY`

### TC-SIM-02：SIM_CB 回调与 SIM_AT 一致性
- 正常情况：两值相同
- 异常情况（SIM 拔出）：两值均变为非 READY

### TC-SIM-03：SIM 热拔出检测
- 运行中拔出 SIM
- 预期：`sim_card_status_cb` 触发，`g_sim_app_ready=0`
- 日志：`SIM Card disconnected during runtime`
- 附带 AT 层快照：`QSIMSTAT`、`CEREG` 输出、dmesg SIM 相关内核日志

### TC-SIM-04：SIM 重新插入恢复
- 插回 SIM 后回调触发，`g_sim_app_ready=1`
- 若断网时长 > 5min（L0 已过），日志 `SIM recovered, forcing immediate L1 recovery`

### TC-SIM-05：回调初始化前的降级查询
- 模拟 `g_sim_app_ready=-1`（回调未触发，理论上 SDK 初始化失败）
- 预期：`ST_SIM` 降级为 `AT+CPIN?` 一次性查询，日志 `g_sim_app_ready=-1` 相关内容

### TC-SIM-06：SDK CP 服务崩溃检测
- 触发 `data_call_service_error_cb`（模拟 CP 侧崩溃）

### 12.2 注册超时处理（`reg_timeout_handler`，EG25 独有代码路径）

EG25 状态机中 `reg_check` / `cereg_check` 超过 `REG_CHECK_TIMEOUT_SECONDS(300s)` 后触发 `goto reg_timeout_handler`，有三条分支，与心跳驱动的切换逻辑相互独立。

#### TC-EG25-REG-01：注册超时 + policy=1/2 + Roamlink 可用 → 切 Roamlink
- 前提：`network_select=1` 或 `2`，Roamlink 完整就绪，物理 SIM 被运营商禁卡（CEREG stat=3）或拔除
- 代码路径：`reg_check` 或 `cereg_check` 等待 300s → `reg_timeout_handler` → `roamlink_start_service()`
- 预期：日志 `[REG TIMEOUT] policy=X, switching to Roamlink`，`is_roamlink_active=true`，`dial_timer` 重置
- 验证：`cat /tmp/dial_Status | grep channel` 显示 ROAMLINK，Roamlink 通道正常 ping 通

#### TC-EG25-REG-02：注册超时 + policy=4 / Roamlink 不可用 → CFUN 重置重走
- 前提：`network_select=4`（或 RBMaster 不存在），SIM 注册超时
- 代码路径：`reg_timeout_handler` → `dial_stat_stop_cfun` → `dial_stat_start_cfun` → `dial_stat_sim_init`
- 预期：日志 `[REG TIMEOUT] policy=4, cfun reset and retry`，`AT+CFUN=0` / `AT+CFUN=1` 执行，重走注册流程
- 验证：SIM 重新注册成功后正常联网，不触发 Roamlink 切换

#### TC-EG25-REG-03：Roamlink 运行中，物理 SIM 注册失败不触发 reg_timeout_handler
- 背景：Roamlink 激活时，状态机处于 `roamlink_starting` 或 `roamlink_active`，而 `reg_timeout_handler` 只能从 `reg_check`/`cereg_check` case 触发，因此该路径天然不可达。旧代码中此处有死代码守卫（已在 v1.32 中删除）。
- 前提：`is_roamlink_active=true`（状态为 `roamlink_starting`/`roamlink_active`），Roamlink 正常 ping 通，物理 SIM 因 RBMaster 占用而注册失败
- 预期：**`reg_timeout_handler` 不被触发**，状态机保持 `roamlink_starting`/`roamlink_active`，Roamlink 心跳正常，无 cfun 重置，无通道切换
- 验证：运行 30min，`cat /tmp/dial_Status | grep state` 始终为 `roamlink_starting` 或 `roamlink_active`，日志中无 `[REG TIMEOUT]` 输出

### 12.3 EG25 拨号状态机边界

#### TC-EG25-ND-01：`net_connected` 状态 120s 无 rx_packets → 重走注册
- 前提：EG25 平台，已进入 `dial_stat_net_connected`，人为屏蔽网卡数据（如 iptables drop 出站包）但不断开 PDP
- 代码路径：`DIAL_TIMEOUT_SECONDS(120s)` 内 `if_rx_packets` 不增长 → `dial_st = dial_stat_reg_check`

### 12.4 EG25 业务层 rx_packets 监测（Problem 8，仅 EG25 + Roamlink 激活时）

#### TC-EG25-BIZ-01：`roamlink_active` 状态下 120s rx_packets 无增长 → 切 SIM（policy=1/2）

## 十三、边界与异常场景

### TC-EDG-01：Roamlink 通道切换与 L1/L2/L3 不同时触发
- 策略1/2/3（EG25）：`dial_st == roamlink_starting` 或 `roamlink_active` 时，L1/L2/L3 被条件 `dial_st != roamlink_starting && dial_st != roamlink_active` 屏蔽
- 策略1/2/3（EC200A）：`is_roamlink_active=true` 时，L1/L2/L3 被 `!is_roamlink_active` 屏蔽
- 验证：Roamlink 失败时，只执行通道切换（或服务重启），不触发 CFUN；`/tmp/cfun_count.txt` 不增长

### TC-EDG-02：网络恢复后所有计时器清零
- 断网 → L1 触发 → 网络恢复 → `start_fail_ts=0`、`last_l1_ts=0`、`last_l2_ts=0`（EC200A）/ `last_recovery_ts=0`（EG25）
- 再次断网：各级阈值重新从 0 计算

### TC-EDG-03：Roamlink 回切失败后计时重置
- Policy1 SIM → 回切 Roamlink 失败
- 预期：`roamlink_fail_count++`，`sim_fallback_ts` 重置为当前时刻，300s 后再次尝试

### TC-EDG-04：license 文件写入中途被读（稳定性检测）
- `roamlink_license_appeared()` 两次 stat 相差 2s，文件大小变化时返回 false
- 模拟：向 license 路径写入文件时同时触发轮询，验证不误判为 license 可用

### TC-EDG-05：Ping 抖动过滤
- 仅 1~2 次 ping 失败，`start_fail_ts` 不应被设置（PING_FAIL_THRESHOLD=3）
- 第 3 次失败时 `start_fail_ts` 才设置

### TC-EDG-06：`cfun_count.txt` 与 `cfun_last_call.txt` 持久化（EC200A L2）
- L2 执行后，验证两文件内容正确
- 重启后重新读取，值持续累计
