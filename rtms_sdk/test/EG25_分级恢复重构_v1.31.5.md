# EG25 分级恢复重构说明（v1.31.4 → v1.31.5）

> 范围：仅 **rtms_sdk** 仓库的 EG25 平台（`eg25/dial/dial.c`、`eg25/dial/dial.h`）。
> 对应提交：`b1bdc423e2190c9e0d928fef11389e9bf4d7660a`（分支 `develop/rtms_sdk_v1.3_20240408_dc_switch`）。
> 版本：`MODEM_MNG_VERSION` 1/31/4 → 1/31/5。
> 不含独立仓库 `open_dial` 的同类清理（那是 EC200A 的上游参考，单独处理）。
> 行文为「改前 vs 改后」逻辑、触发点、条件整理；结论为代码层面确定性，非设备实测。

---

## 一、一句话总结

本次只动 **策略4（强制物理 SIM，`NET_POLICY_FORCE_SIM`）** 下的断网分级恢复，做三件事：

1. **修问题 A**：分级恢复改为**纯断网时长（downtime）驱动**，移除「SIM 恢复即立即触发 L1」（`sim_error_active`）整套逻辑——消除复位走完误打的一条 `[RECOVERY L1] SIM recovered`。
2. **修问题 B**：策略4 的 **CFUN 射频复位归 L2 独占**——已连通过之后注册超时处理（reg_timeout）让位，不再与 L2 在同一段卡死期对模组各复位一次。
3. **日志降噪**：`[INIT]` 静态信息（ICCID/IMSI/IMEI/PDP/FW/policy）只在首次进入 `sim_op` 打印一次。

另含一处兼容性整理：IMEI 解析块声明提至块首（兼容 EG25 gnu89 工具链）。

### 据此归纳出两个独立问题

## 三、核心概念（读懂前置）

| 名词 | 含义 |
|---|---|
| `net_ok` | `test_can_ping_google()` 的结果，**纯 ping 8.8.8.8**，与状态机无关 |
| `start_fail_ts` | ping 连续失败达阈值后置位的「故障起点」时间戳 |
| `downtime_sec` | 断网时长 = now − `start_fail_ts`；ping 恢复即清零 |
| `has_connected_once` | 本进程**确认连通过至少一次**（首次 ping 成功，或开机即已联网的暖启动）后永久置 1 |
| `dial_st` | 拨号状态机；本文涉及 `reg_check`/`cereg_check`/`net_connected`/`stop_cfun`/`start_cfun`/`sim_init`/`sim_check`/`sim_op` 等 |
| `network_policy` | 1=优先Roamlink 2=优先SIM 3=强制Roamlink **4=强制SIM(FORCE_SIM)** |
| **L1/L2/L3** | 断网分级恢复，**仅策略4**启用，按 downtime 升级 |
| **reg_timeout** | `reg_timeout_handler`，注册超时（reg_check/cereg_check 卡死 300s）后的策略分派器 |
| `sim_error_active` | （**本次已删**）原「SIM 曾掉、恢复时立即触发 L1」的标志 |

**关键认知：策略4 下原本同时存在两套恢复机制**——L1/L2/L3（从 EC200A 参考 `open_dial` 借来）与 reg_timeout（从 EG25 上游 `open_dial_for_artery` 同步而来）。两者会对同一模组各自做 CFUN 复位，这是 B 的根；而 `sim_error_active` 在自发复位窗口读到 SIM:0 误置位，是 A 的根。

## 四、修改逐项（改前 vs 改后）

### 4.1 移除 `sim_error_active`：分级恢复改纯 downtime 驱动（修 A）

| | 改前 | 改后 |
|---|---|---|
| 标志 | 有 `sim_error_active` | **删除** |
| 置位 | 每轮读到 SIM:0 即置（电平触发，无守卫） | 不存在 |
| L1 触发 | 两条：① SIM 恢复立即触发；② downtime 定时 | **一条**：仅 downtime 定时 |
| 「SIM recovered」日志 | 会打 | 不存在 |
| 恢复判级 | 先判 `sim_error_active` 立即 L1，否则走 downtime 阶梯 | 直接走 downtime 阶梯 |
| 对外 nano 发布 ICCID/IMSI | 每次 sim_op 刷新 | **不变**（仍每次刷新） |

逻辑要点：A 的根是「自发关 RF 期间 SIM:0 被当真掉卡」。改后恢复完全不读 SIM 状态来触发 L1，根上消除误判；SIM 真掉卡仍由后续 downtime 升级正常恢复（拔卡→ping 不通→downtime 增长→L1/L2/L3）。

### 4.2 L2 独占 CFUN + reg_timeout 让位（修 B）

| | 改前 | 改后 |
|---|---|---|
| 谁做 CFUN（策略4 已连过、卡 reg_check） | L2 **和** reg_timeout 各做一次（双复位） | **仅 L2**；reg_timeout 让位 |
| reg_timeout 策略4分支 | 一律 `stop_cfun` 做 CFUN 复位 | 已连过→**让位**（只重置 `dial_timer`、不复位）；未连过→照常复位 |
| L2 自身 | 内联 CFUN（无条件） | 内联 CFUN（无条件，不变） |
| reg_timeout 对策略1/2/3 | Roamlink 切换 / 复位 | **完全不变** |

逻辑要点：让 L1/L2/L3 成为策略4 已连过时的唯一恢复主，CFUN 由 L2 的 downtime 阶梯单次触发；reg_timeout 在该情况下任何状态都不再碰 CFUN（连「跨阶段」双复位也一并消除）。冷启动（尚未连通）时 L1/L2/L3 被 `has_connected_once` 门控关闭，reg_timeout 仍做复位兜底。

> 补充事实：reg_timeout 复位比 L2 多走的 `sim_init`(`QL_MCM_SIM_Client_Init`)+ 重读 ICCID/IMSI，经核 `sim_op()` 实现，仅是「读 SIM 标识」的客户端句柄重建与标识重读，与网络恢复无关、ICCID/IMSI 运行期不变；L2 跳过这两步、由状态机 `reg_check→cereg→precondition→start_call` 自身重建数据呼叫，无功能损失。

### 4.3 `[INIT]` 静态信息只打一次（Q10 降噪）

| | 改前 | 改后 |
|---|---|---|
| `[INIT] ICCID/IMSI/IMEI/PDP/FW/policy` | 每次进 sim_op 都打（含每次 cfun 重初始化，约每 5min 重刷） | 由 `init_info_logged` 门控，**仅首次 sim_op 打一次** |
| 附带的 AT 查询（IMEI/PDP/FW） | 每次重初始化都查 | 仅首次查 |
| nano 发布 ICCID/IMSI | 每次刷新 | **不变**（在门控外） |
| `[MODEM]` 块 | 启动只打一次（在 `dial_stat_init`，cfun 复位不回该状态） | **不变** |

### 4.4 IMEI 解析 C89 整理（兼容性）

将 IMEI 解析块内的指针声明提至块首，兼容 EG25 默认 gnu89 工具链；无行为变化。

## 六、多条件整理（分层）

### 6.1 恢复块外层门控（5 条，全满足 L1/L2/L3 才评估）

1. `!net_ok`（ping 不通）
2. `start_fail_ts > 0`（故障计时已起）
3. `has_connected_once`（曾连通过——冷启动首拨阶段关闭，防干扰初始拨号）
4. `dial_st` 非 `roamlink_starting` 且非 `roamlink_active`
5. `network_policy == NET_POLICY_FORCE_SIM`（策略4）

### 6.2 downtime 阶梯（互斥 else-if，L3 优先防退化横跳）

| 判级顺序 | 条件 | 结果 |
|---|---|---|
| 1 | `downtime ≥ 1800s` | L3 |
| 2 | `downtime ≥ 300s` 且 (无上次L2 或 距上次L2≥300s) | L2 |
| 3 | `downtime ≥ 60s` 且 (无上次L1 或 距上次L1≥60s) | L1 |
| 否则 | — | 不动作 |

> 关键：到 300s 即进入 L2/L3 区间，**结构上回不到 L1**——这是「复位后不会再误判成 L1」的保证之一。

### 6.3 reg_timeout 三岔分派条件（见五节表）

### 6.4 `has_connected_once` 的双阶段语义

| 阶段 | L1/L2/L3 | reg_timeout（策略4） |
|---|---|---|
| 冷启动（未连过，=0） | 关闭 | 做 CFUN 复位（唯一兜底） |
| 已连过（=1） | 开启 | 让位（不做 CFUN） |

## 七、CFUN 复位所有权矩阵（改后）

| 策略 | 场景 | 谁做 CFUN | reg_timeout 行为 |
|---|---|---|---|
| 4 | 已连过，断网卡 reg_check | **L2 独占**（每 5min） | 让位（`defer cfun reset to L2 ladder`） |
| 4 | 已连过，net_connected 数据面死 | **L2**（reg_timeout 本就不从此触发） | — |
| 4 | 冷启动（未连过） | **reg_timeout** | `cfun reset and retry` |
| 1/2 | reg 超时 + Roamlink 可用 | 不做 CFUN（切 Roamlink） | 切 Roamlink |
| 1/2 | reg 超时 + Roamlink 不可用 / license_pending | **reg_timeout** | `cfun reset and retry` |
| 3 | — | 不走物理 SIM 路径 | 不涉及 |

> 注：另有两条与「断网恢复」无关的 CFUN 路径任何策略都在——`sim_check` 1 小时检测不到 SIM、`list_oper` 选网流程末尾，本次未改动。

## 十一、根因链分析（问题 A / 问题 B）

### 11.1 问题 A —— 误打立即 L1 的根因链

| 步骤 | 发生了什么 |
|---|---|
| ① | 策略4、已连过、长断网 → 状态机卡在 `reg_check`（注册不上）。 |
| ② | reg_timeout（进 reg_check 满 300s）触发 → `dial_st` 进入自发复位流水线 `stop_cfun → start_cfun → sim_init → sim_check`。 |
| ③ | 该流水线里 `AT+CFUN=0` 关掉了射频；与此同时 30s 心跳并发执行 `nw_get_sim_card_status()`，读到 **SIM:0**（图2 21:06:28）。 |
| ④ | 旧逻辑 `if(!sim_ok) sim_error_active=1`（**电平触发、无守卫**）把"自己关 RF 导致的 SIM:0"误判为真掉卡，置位。 |
| ⑤ | 复位走完 SIM 回到 1 → `if(sim_error_active && sim_ok)` 命中 → 强制 `recovery_level=1`（**无视 downtime**）→ 打 `[RECOVERY L1] SIM recovered, forcing immediate L1`（图2 21:06:59，此刻 DownTime≈1350s 本应是 L2）。 |

**为什么这么修能根除**：移除 `sim_error_active` 后，恢复**完全不读 SIM 状态来触发 L1**；L1 只由 `downtime ∈ [60s,300s)` 触发，而任何复位发生时 downtime 早已 ≥300s、落入 L2/L3 区间，阶梯互斥**结构上回不到 L1**。因此无论复位期是否读到 SIM:0，都不可能再误打 L1（根除，而非压制）。

### 11.2 问题 B —— 双 CFUN 复位的根因链

| 步骤 | 发生了什么 |
|---|---|
| ① | 策略4 同时挂着**两套恢复机制**：L1/L2/L3（借自 open_dial）与 reg_timeout（来自 open_dial_for_artery）。 |
| ② | 二者基于**不同时钟**：L2 看 `downtime`（从 ping 失败起算），reg_timeout 看 `dial_timer`（从进 reg_check 起算），阈值都约 300s。 |
| ③ | 长断网卡 `reg_check` 时，两个计时器先后到点，各自发一次 `AT+CFUN=0/1`（图2：L2 21:04:56 + reg_timeout 21:06:22）。 |
| ④ | 两次复位间隔约 1.5min，**后一次打断前一次刚发起的注册**，恢复反而被拖慢。 |

**为什么这么修能根除**：让 CFUN 在「策略4 + 已连过」时**归 L2 独占**——reg_timeout 在该情况下让位（不做 CFUN，仅重置 `dial_timer` 防紧循环）。这样无论哪个时钟先到点，CFUN 只由 L2 单次发出，reg_timeout 不再产生第二次复位。冷启动（未连过）时 L2 被门控关闭、由 reg_timeout 兜底，二者不会同时存在，故无空窗。

## 十二、状态机流转与 CFUN 入口示意图

```
开机
 └─ none → init → sim_init → sim_check → sim_op → reg_check ⇄ cereg_check
                                                      │             │
                                                (卡死300s)     (卡死300s)
                                                      └──────┬──────┘
                                                             ▼
                                                  reg_timeout_handler
                                              ├ 策略1/2 + RL可用 → roamlink_starting（切RL，不做CFUN）
                                              ├ 策略4 + 已连过   → 让位：仅重置dial_timer，不做CFUN
                                              └ 否则             → stop_cfun  ◄── CFUN入口①
                                                 (策略4冷启动 / 策略1/2 RL不可用 / license_pending)

   precondition_check → pre_start_call → start_call → wait_for_connect → net_connected
            ▲                                                                  │
            └────────────────── (注册成功后状态机自行建呼叫) ───────────────────┘

进入「stop_cfun→start_cfun→sim_init→sim_check→…」自发复位流水线的 CFUN 入口：
  ① reg_timeout_handler（else 分支）  ── 策略4冷启动 / 策略1/2 RL不可用 / license_pending
  ② sim_check 1 小时超时             ── 任何策略，SIM 检测不到满 1h
  ③ list_oper 选网流程末尾           ── 配置了运营商选择时

L2 的 CFUN：在恢复块内**内联**执行 AT+CFUN=0/1，**不经 stop_cfun 状态**，dial_st 保持原值（如 reg_check）。
```

**撞点说明**：B 发生在「卡 `reg_check` 时」——L2 内联复位 与 reg_timeout 经入口① 复位**同段时间各做一次**。本次改动让入口① 在「策略4 + 已连过」让位，**撞点消除**；入口 ②③ 与本问题无关、未改动。

## 十三、两种 CFUN 复位为何不等价（L2 vs reg_timeout）

| 维度 | reg_timeout 复位（经 stop_cfun） | L2 内联复位 |
|---|---|---|
| CFUN 命令 | `AT+CFUN=0/1`，**带 AT 重试**（最多 `AT_RETRY_NB` 次） | `AT+CFUN=0/1`，单发 |
| 复位后路径 | `stop_cfun→start_cfun→sim_init→sim_check→sim_op→reg_check→…→start_call` | `dial_st` 不变（停 reg_check），由状态机自身后续 `reg_check→…→start_call` |
| 额外动作 | `sim_init`=`QL_MCM_SIM_Client_Init`（重建 SIM 客户端句柄）+ `sim_op`（重读 ICCID/IMSI） | 无 |
| 数据呼叫重建 | 经 `precondition→start_call` | 同样经 `precondition→start_call`（状态机） |

**结论**：reg_timeout 多出的 `sim_init`/`sim_op` 只是「读 SIM 标识」的**客户端句柄重建 + 标识重读**——`QL_MCM_SIM_Client_Init` 初始化的 `h_sim` 句柄**只**被 `GetICCID`/`GetIMSI` 使用，与「注册 / 数据呼叫」恢复无关；ICCID/IMSI 运行期不变且已缓存。数据呼叫重建两条路径**都有**。故 L2 跳过这两步**无功能损失**。

**诚实保留**：「`h_sim` 在 CFUN 后绝不需要重建」无 Quectel 文档级证明；但从用途（仅读标识）、句柄性质（app 侧 IPC）、以及 L2 轻量复位本就是 `net_connected` 卡死时的既有行为（一直在跑且 work）三点判断，跳过为**高置信无害**。

## 十四、非恢复类 CFUN 路径（与断网恢复无关）

| 入口 | 触发条件 | 作用 | 本次是否改动 |
|---|---|---|---|
| `sim_check` 1 小时超时 | SIM 卡连续 1 小时检测不到（`SIM_CHECK_TIMEOUT`） | `dial_st=stop_cfun` 做 CFUN 复位重试 | 否 |
| `list_oper` 选网末尾 | 配置了运营商选择（`is_oper_select`），选完运营商后应用 | `dial_st=stop_cfun` 经 CFUN 周期生效 | 否 |

**说明**：这两条属于正常拨号 / SIM 缺失流程，**不是**断网分级恢复的一部分。它们同样会进入 `stop_cfun→…→sim_init` 流水线——也正因如此，**改前**它们也会让心跳采到 SIM:0 → 误置 `sim_error_active`（A 的另一可能触发面）；**改后** `sim_error_active` 已删，此隐患一并消失。两者自身行为本次未改动。

## 十五、上游对齐背景（嫁接史，超出纯 rtms_sdk 范围，仅作背景）

> 本节解释「为什么 EG25 会同时有两套恢复」，涉及独立参考仓库，仅作背景，不属于本次代码改动。

- **对齐关系**：EC200A ← `open_dial`；EG25 ← `open_dial_for_artery`（每平台逐条对齐各自参考）。
- **L1/L2/L3 分级恢复**：EG25 是**借自 `open_dial`**（EC200A 的参考），`dial.c` 注释也写"open_dial 设计"。
- **reg_timeout（注册超时切换策略）**：来自 EG25 真正上游 **`open_dial_for_artery`**（同步自其提交 `9d1583397...`）。
- **经核实**：`open_dial_for_artery` 本身**无 L1/L2/L3、无 `sim_error_active`**，恢复纯靠 reg_timeout。
- **结论**：EG25 同时存在两套恢复 = **两个上游嫁接的产物**，正是 A（`sim_error_active` 误置）与 B（双 CFUN）的**结构性来源**。本次修复（纯 downtime + L2 独占 CFUN）使 EG25 回到「单一恢复主」，也更贴近上游不重复复位的形态。
- **补充**：`sim_error_active` 在 `open_dial` 是**边沿触发 + `has_notified_connect` 守卫**的稳健版；移植到 EG25 时退化成**电平触发、无守卫**，这是 A 在 EG25 更易触发的原因之一。
