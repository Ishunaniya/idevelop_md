## 2. 逐章全量内容

### 第 1 章 引言

- 介绍 AG35-CET/EUT 的**强发（TX）和强收（RX）AT 命令**，用于 **FTM 工厂测试模式**下验证射频收发功能。

### 第 2 章 AT 命令详解

- **命令前缀为 `AT*`**（非常规 `AT+`）：测试 `AT*<cmd>=?` / 查询 `AT*<cmd>?` / 设置 `AT*<cmd>=<p1>...` / 执行 `AT*<cmd>`。
- 三条命令最大响应时间均 **300 ms**；特性均为**立即生效、参数不保存**。

#### 2.3.1 `AT*LTETR` — LTE 射频测试

```
AT*LTETR=<op>,<band>,<power>,<bandwidth>
响应（强收）: +LTEPOWER:0,,,rssi_Pri=<measured_power>
```

- `<op>`：`0` LTE 强发 / `1` LTE 强收。
- `<band>`：强发/强收频段编码不同（强发如 1=18300、2=18900…41=40620；强收如 1=300、2=900…41=40620）。
- `<power>`：强发 `0`=APC1900 / `1`=APC1700；强收 `0`=目标 -50dBm / `1`=目标 -60dBm。
- `<bandwidth>`：固定 `0`。
- `<measured_power>`：功率测量值，单位 dBm。
- **备注**：① 退出测试执行 `AT*LTETR=0,1,9`；② **进测试前须 `AT+CFUN=0` 关闭 modem**。

#### 2.3.2 `AT*WBTR` — WCDMA 射频测试

```
AT*WBTR=<op>[,<dlUarfcn>,<ulUarfcn>[,<paMode>[,<apcDac>[,<afcDac>]]]]
响应: *WBTR:<measured_power>
```

- `<op>`：`0` 强发 / `1` 强收 / `2` 停止。
- `<dlUarfcn>`/`<ulUarfcn>`：上下行 UARFCN（分段范围，如下行 10562~10838 等）。
- `<paMode>` 0~2；`<apcDac>`/`<afcDac>` 因 RF 卡而异（GONGGA：apcDac 默认 1600/0~2047，afcDac 默认 18000/4000~32000；Mynah：apcDac 默认 800/0~880，afcDac 默认 0/-512~512）。
- **备注**：进测试前须 `AT+CFUN=0`。强发时返回值无意义。

#### 2.3.3 `AT*GSMTR` — GSM 射频测试

```
AT*GSMTR=<op>[,<band>,<arfcn>,<afcDac>[,<txRampScale>,<rxGainCode>]]
响应: *GSMTR:<measured_power>
```

- `<op>`：`0` 强发 / `1` 强收 / `2` 强发强收 / `3` 停止。
- `<band>`：1=PGSM900 / 2=DCS1800 / 4=PCS1900 / 8=EGSM900 / 16=GSM450 / 32=GSM480 / 64=GSM850。
- `<arfcn>`：随频段不同范围（PGSM900 1~124、DCS1800 512~885 等）。
- `<afcDac>` 5000~32000；`<txRampScale>` 仅强发 0~1023（建议 200~700）；`<rxGainCode>` 仅强收 0~49。
- **备注**：进测试前须 `AT+CFUN=0`。

### 第 3 章 举例（实操序列）

```
// LTE
AT*LTETR=0,1,0,0     // BAND1 强发最大功率
AT*LTETR=0,1,9       // 退出强发
AT*LTETR=1,1,1,0     // BAND1 强收（仪器先发偏移0.1MHz、-60dBm CW），返回 rssi_Pri=-60
// WCDMA
AT*WBTR=0,10700,9750,2,1600,18000   // 强发（返回值无意义）
AT*WBTR=2                           // 停止
AT*WBTR=1,10700,9750,2,1600,18000   // 强收，返回测量值
// GSM
AT*GSMTR=0,1,10,6000,700,20         // PGSM900 ARFCN10 强发
AT*GSMTR=1,1,10,6000,200,20         // 强收（仪器先发偏移0.05MHz、-60dBm CW），返回 -61
AT*GSMTR=3                          // 停止
```

### 第 4 章 CMW500 配置

- 强收用信号源（如 CMW500）发**连续波 CW**：设线损补偿、接收信号频偏 500 kHz、设接收信号功率、信号模式设为 CW。

## 3. 关键警告与坑（手册"备注"汇总）

1. **进入任何强发/强收测试前必须 `AT+CFUN=0` 关闭 modem** —— 否则射频测试与正常协议栈冲突。
2. **命令前缀 `AT*` 非 `AT+`** —— 易写错。
3. **参数不保存、立即生效** —— 掉电/重启失效，纯临时测试态。
4. **退出方式各异**：LTE `AT*LTETR=0,1,9`；WCDMA `AT*WBTR=2`；GSM `AT*GSMTR=3`。
5. **临时版本，参数未完全验证** —— apcDac/afcDac 等因 RF 卡型号（GONGGA/Mynah）不同，照搬可能不准。
6. **强发返回值无意义**（WCDMA/GSM），只有强收的 `<measured_power>` 才是真实测量。

## 4. 对 open_dial 项目的适用性批注

> open_dial 是运行期拨号守护进程；RF FTM 是**产线/实验室射频校准与验证**手段，**两者生命周期完全不重叠**。本文档面向 AG35 车载模块，EC200A 的 FTM 命令/频段编码大概率不同，**不可照搬**。

| 文档内容 | 与 open_dial 的关系 / 可借鉴点 |
|---|---|
| **进 FTM 须 `AT+CFUN=0`** | 与 open_dial 恢复逻辑里的 `AT+CFUN=0/1`（L2 射频重置）是同一族命令，但语义不同：这里是为射频测试彻底关 modem。提醒：**FTM 测试与 open_dial 不能同时跑**——测试期间 modem 关闭，拨号守护会一直判断断网并触发恢复，产线测试前应停掉 open_dial。 |
| **`AT*` 强收测量 RSSI/功率** | 仅在**怀疑硬件射频/天线问题**导致"信号差→频繁掉网→反复 L1/L2/L3"时，作为**硬件侧排查工具**：用 FTM 强收测灵敏度，区分是"天线/射频硬件劣化"还是"软件/网络侧"问题。属 open_dial 排障的**外围旁证手段**，不进代码。 |
| **临时版本、参数因 RF 卡而异** | 提醒：射频参数高度依赖具体硬件批次，open_dial 不应假设任何射频参数。 |

**结论**：本文档对 open_dial **相关度最低**，与拨号守护代码无任何耦合。唯一价值是**产线/硬件排障的旁证工具**：当软件层恢复逻辑（L1/L2/L3）反复触发却查不出软件原因时，可用 FTM 强收命令排查是否射频硬件/天线问题。**注意**：跑 FTM 必须先停 open_dial（FTM 会 `AT+CFUN=0` 关 modem，否则守护进程会误判断网狂触发恢复）。
