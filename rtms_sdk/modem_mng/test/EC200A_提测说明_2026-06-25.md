## 2. 怎么配置

### 2.1 编译/烧录
```bash
export QL_MODULE_PLATFORM=EC200A
export QL_SYSROOT_DIR=<EC200A_SDK_sysroot>
cmake -B build -S . && cmake --build build
cmake --install build --prefix <install_path>
```

### 2.2 运行依赖与外部配置
- **SIM**：物理卡，需有数据流量；专网卡依赖 APN 配置（见下）。
- **APN**：启动时按 ICCID 匹配 `apn.json`，写入数据呼叫 profile `DATA_CALL_APN_PUBLIC(=6)`；匹配不到则用模组自动 APN。
- **网络阈值/流量阈值**：`/etc/config/config.json`（`parse_config.hpp` 解析）；其中键 `C020102` = 流量上限 `PacketLimit`（未配置则不做流量超限判断）。
- **SD 卡**：挂载 `/media/sdcard`，初始化要求可用空间 ≥500MB（否则日志不落 SD，仅 stdout）。
- **看门狗/init**：必须能在进程 `exit` 后重新拉起 modem_mng（L3 与快速失败均依赖它重启自愈）。
- **依赖工具**：设备需有 `serial_atcmd`、`ping`、`iptables`、Quectel SDK 运行库。

### 2.3 内置策略阈值（编译期常量，非运行时可配）
- 分级恢复阈值 L1/L2/L3 = 5min / 10min / 35min，硬编码于 `ec200a/dial/dial.cpp:1204-1206`。
- 应用层恢复总开关 `enable_policy_recovery`（默认 1，`dial.cpp:565`）。
- 快速失败：`/tmp/dial_retry_count`，上限 3 次（`MAX_FAST_RETRY_TIMES`）。

## 3. 行为是什么样

### 3.1 启动与首连
启动顺序：初始化日志 → 建立 CP dump 捕获（bind-mount `/sdcard`）→ **等 `ccinet0` 网卡就绪最多 30s，不就绪则 `exit -1`**（由看门狗重拉）→ **注册到 sw_mng（进程名 `modem_mng`、版本、看门狗超时 60s）** → 写 `/tmp/dial_version` → 起 nanomsg/事件发布/流量监控 → 起拨号线程。
拨号线程内：初始化数据呼叫服务 → SIM 初始化、读 ICCID、写 APN → 创建/配置/启动 data call（call_name=`auto_network`）→ 打印启动诊断（IMEI/固件/IMSI/运营商/CFUN/PDP 等）→ 进入 50ms 巡检循环。首次 ping 通即对外发"已连接"通知并配置系统默认路由/DNS/NAT。
注：main 另会等"拨号成功（网卡名出现）"最多 60s，**超时仅提示、不杀拨号循环**（弱信号首拨可能 >60s，交由 Fast-Fail/分级恢复自行处理）。
首次 ping 成功后还会一次性保存时区：取 `date -R` 的偏移换算为 15 分钟单位写入 `/usr/dial/tz.ini`（`[dev] tz=`，东八区=32）。
路由默认仅 IPv4（`ip_ver=QL_NET_IP_VER_V4`）；仅当数据呼叫回调带 IPv6 地址时才下发 `ip -6 route`，默认配置下不走 IPv6 分支。

### 3.2 巡检循环
循环每 50ms 推进一个阶段：读拨号状态 → 查 SIM（含网络注册）→ 查信号(CSQ) → ping `8.8.8.8`（`ping -c 1 -W 2`，含 `ttl=` 判成功）→ 必要时进恢复。ping 连续失败 3 次才判定故障开始（抖动过滤）。

### 3.3 分级恢复（核心）
故障计时从"判定故障"起算（`start_fail_ts`）。门控：**只有曾成功连上过（`has_connected_once`）才启用 L1/L2/L3**；从未连上过的设备恒留在 L0，断网超 10min 仅打一次 `never-connected ... gated` 日志（推断为 SIM/账户问题）。

| 阶段 | 何时 | 做什么 |
|---|---|---|
| **L0** | 0–5min | SDK 每 25s 自动重连，应用层不干预 |
| **L1** | >5min 且已注册(REG≠0) | 软重拨：停止+重启 data call；同档最快 60s 一次 |
| **L2** | >10min；或 REG=0 且 >5min | 射频重置：`AT+CFUN=0`→`=1` 后重启 data call；冷却 REG=0 时 90s、否则 5min |
| **L3** | >35min | `exit(1)` 退出，由看门狗/init 重拉、重走完整初始化 |

要点：L3 是纯进程退出（**不是**整机/模组 `cfun=1,1` 重启——OpenCPU 下那会连累同机其它业务）；它能拿到干净的 SDK 客户端状态，但清不掉 CP 固件级 hang（已知取舍）。SIM 运行期掉卡会单独打 `[ERROR] SIM Card disconnected`+诊断，恢复 READY 后按断网时长走正常恢复（不强制立即重拨）。

### 3.4 快速失败（启动期自愈）
前 3 次启动：PDP 60s 内建不起、或 PDP 起来但 10s 内 ping 不通，即 `exit(1)` 让看门狗快速重启重试；第 4 次起转持久模式不再快退。首次 ping 成功清空计数。

### 3.5 LED（仅 EC200A）
在线=常亮、断网且在 L0 等待=灭、进入分级恢复/首连前=闪烁；仅状态变化时下发指令（边沿触发，不刷屏）。

### 3.6 流量监控
读 `config.json` 键 `C020102` 为流量阈值 `PacketLimit`，监控数据网卡：本月累计流量超阈值（且阈值>0）发布 `TrafficOverLimit` 事件；数据网卡 60s 无收发发布 `NoTraffic` 事件；每月 1 号本月累计清零（取历史差值）。阈值未配置（0xffff）时打 `not define packet limit`、不触发超限。

### 3.7 对外接口（IPC）
- **状态查询** REQ/REP `tcp://127.0.0.1:38001`：请求 JSON `{"ts":..,"status":{"network":["cellular"]}}`，回包 `status.network.cellular` 含 iccid/csq/operator/register/network_type/plmn/network_online/ip/dns1/dns2/gateway 等字段。畸形/异常请求被捕获并节流记日志，**不会拖垮进程**（本版本已加 try/catch + 类型校验加固）。
- **事件发布** PUB `tcp://127.0.0.1:48001`：发布网络状态变化、`TrafficOverLimit`、`NoTraffic` 等事件。

### 3.8 日志与诊断
- 日志同时输出 stdout 与 SD：`/media/sdcard/dial_log/YYYY-MM-DD/dial_HHMMSS.log`，按天分目录、保留 40 天 + 1024MB 空间兜底、跨午夜轮转；时钟同步前的日志先进 `unsynced/`。主循环与 SDK 回调线程共用递归锁写日志。
- 30s 心跳 `[HEARTBEAT]`（SIM/REG/CSQ/温度/断网时长）；首连后每 5min 扩展心跳（信号/小区/IP）。
- 故障/恢复时落 `dmesg+logcat` 快照到 `dial_log/dial_snap/`；bind-mount `/sdcard` 保留 CP 崩溃 dump（均需 SD 可用、且已连过一次）。

### 3.9 退出
收到 SIGTERM/SIGINT 置退出标志，灭灯后退出循环，主线程 join 后做 teardown 与 log 关闭。

## 4. 怎么观察

### 4.1 运行期状态文件
| 文件 | 含义 |
|---|---|
| `/tmp/dial_version` | `Version: 1.31.5` |
| `/tmp/dial_Status` | 0=连接 1=断开 |
| `/tmp/network_status` | 0=down 1=up |
| `/tmp/dial_retry_count` | 快速失败计数（连通后清除） |
| `/tmp/cfun_count.txt` / `/tmp/cfun_last_call.txt` | CFUN 计数/时间（注：当前恢复路径未用此限流，见 §5 R3） |

### 4.2 关键日志标签（grep 用）
`[INIT] [HEARTBEAT] [PING] [EVENT] [ALARM] [RECOVERY L1|L2|L3] [INFO] [ERROR] [DIAG*] [LED] [NANOMSG] [CPDUMP] [FATAL]`
- 故障开始：`[INFO] SDK auto-reconnect phase started`
- 各档触发：`[ALARM] ... Trigger Level N recovery.` 后接 `[RECOVERY LN] ...`
- L3 退出：`[RECOVERY L3] FATAL: Network down 35mins. Exiting...`
- 门控：`[INFO] never-connected, policy recovery (L1/L2/L3) gated`

### 4.3 旁证
`serial_atcmd at+cereg?`（注册）、`at+csq`（信号）、`at+cfun?`（射频）；`ip route` / `iptables -t nat -L`（路由/NAT）；`ls /proc/$(pidof modem_mng)/fd | wc -l` 与 `grep VmRSS /proc/$(pidof modem_mng)/status`（资源）。

## 5. 已知行为/取舍/风险（测试侧须知）

| 编号 | 描述 | 性质 |
|---|---|---|
| R1 | L2 执行内含约 13s 阻塞（CFUN 后等注册），其间心跳/LED/喂狗暂停、退出延迟。但看门狗超时为 60s（`dialer_ec200a.cpp:119`），13s<60s 故误杀风险低 | 设计现状，低危 |
| R2 | REG=0 时 L2 以 90s 冷却反复 CFUN，30min 内可能约 20 次 | 弱网/无服务区下的预期行为 |
| R3 | CFUN 次数限流函数存在但未接入恢复路径，故 R2 无硬上限 | 待评估 |
| R4 | 恢复判断用的 REG 值来自 30s 心跳缓存，最长滞后 30s | 设计现状 |
| R5 | 巡检 ping 实际间隔约 3.1–3.7s（注释写 1.5s），故障判定比首丢包晚约 6–9s | 文档/注释待订正 |
| R6 | L3 为进程退出，清不掉 CP 固件级 hang（仅整机 cfun=1,1 能清，已禁用） | 已知取舍 |
| R7 | SDK 服务崩溃回调当前仅记一次日志、不退出 | 设计现状 |

> R1–R7 为既有设计/取舍或待评估项，非本次提测引入的缺陷。
