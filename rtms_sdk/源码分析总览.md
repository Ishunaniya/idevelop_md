## 源码目录总览

```text
rtms_sdk/apps/                         # 下列目录是不同产品或服务的应用边界
├── dima_client/                        # CAN 点表、场景、MQTT
├── gb32960_client_for_dima/           # CAN/GPS/MCU、GB 32960 TCP 与补传
├── hdx_aux/                            # 常驻辅助入口与 hdx_dev 产测入口
├── iec_app/                            # 本机采集汇聚、IEC 或 MQTT
├── modbus_app/                         # 串口 Modbus RTU 主站、nanomsg PUB
├── webserver/                          # GoAhead 配置页面与导入/导出
├── can_client_for_jinke/               # 金科 CAN 点表与 MQTT
├── cloud_client/                       # 本地/远端 MQTT 桥接与历史缓存
├── lock_client/                        # MQTT 锁控指令与本机命令服务
├── bs_client_heavy_truck/              # 重卡换电站协议、CAN 和控制
├── bs_client_port_crane/               # 港机集卡换电站协议、CAN 和控制
├── gb_client_for_mixer/                # 车型解析、国六/非四、签名与平台
└── web_app/                            # GoAhead 记录查询与日志导出
```

这张树列的是**源码目录**，不是一个统一运行的进程图。每个应用自己的 `main.c`、`src/`、配置资源及编译范围见对应报告的“源码目录总览”；其中 `web_app` 的服务入口位于 `src/src/goahead.c`。顶层 `apps/CMakeLists.txt` 的开关和各目录 CMake 决定目标是否进入构建，构建后仍要核对实际启动入口。

## 核心架构设计

### Dima 数据路径

```text
本机 CAN → dima_client → 点表 / 场景筛选 → MQTT TBOX/REPORT
本机 CAN + GPS + MCU → gb32960_client_for_dima → GB 32960 TCP
                                               └→ 离线文件 → 补传
```

这两条路径对应两个独立目标。场景 MQTT 客户端的服务端接收、GB 32960 的平台确认及历史删除后果，各由对应报告限定。

### 海德信数据路径

```text
串口从站 ↔ modbus_app → 本机 nanomsg PUB ─┐
本机 CAN / GPS 发布端 ───────────────────────┼→ iec_app → IEC 101/104 或 MQTT
                                             └→ 点表与历史任务
浏览器 ↔ webserver → 配置文件 / Excel 转换
hdx_aux 常驻入口 → RS485 服务，并调用 stop/disable modbus_app
hdx_dev 产测入口 → 按命令检查设备；rs485 命令也会调用 stop modbus_app
```

`modbus_app` 的 PUB 地址与 `iec_app` 的 Modbus SUB 地址在两份报告中对应；实际设备上的服务启动、串口和外部对端需要另核。`hdx_aux` 是另一进程，但其常驻 RS485 初始化会调用 `systemctl disable/stop modbus_app`，返回值没有被检查；不能把两者画成互不影响、默认同时工作的链路。其 IEC/MQTT 源文件虽被编译，当前入口没有启动其业务链。

### 金科数据路径

```text
本机 CAN → can_client_for_jinke → mgw:local_ip/local_port 指定的 MQTT Broker
本地 MQTT / 本机命令服务 ↔ cloud_client ↔ 远端 MQTT Broker
配置的 MQTT Broker 上的锁控指令 → lock_client → 本机命令服务 → 锁具/控制器
```

金科 CAN 客户端的 Broker 地址来自配置，`local_ip` 默认值为 `127.0.0.1`。其发布的 `local/data/*` 与云桥接客户端处理的本地主题可以按主题逐项对照，但**源码接口相容不证明三者必然同机部署**。锁控 ACK、本机发送和锁具实际动作也不能合并为一次成功事件。

### 换电、搅拌车与 Web

```text
重卡或港机 CAN / 本机状态 ↔ 各自 bs_client ↔ 换电站 TCP / 本机控制服务
搅拌车 CAN / GPS / MCU → gb_client → 国六或非四 → 签名设备 → 企业平台
浏览器 → web_app / GoAhead → 记录、配置、日志文件与 ZIP 导出
```

两个换电目录是独立项目；在 `bc60961e` 的顶层应用清单中未按常规选项纳入。搅拌车的国家平台备案连接与企业平台数据出口不同。`web_app` 与海德信的 `webserver` 是两个独立源码目录和构建目标。

## 构建与运行边界

- 顶层开关、目录 CMake、最终编译宏、安装文件和设备启动配置是连续的不同阶段。`dima_client`、Dima GB 32960、金科 CAN、`cloud_client`、搅拌车客户端的顶层开关在其报告所用提交中默认关闭；`web_app` 默认开启。两个换电目录须先看是否被顶层纳入。
- `can_client_for_jinke` 的部分宏组合有源码可见的类型/成员可见性问题；编译成功仍不能代替点表、Broker 和现场数据验证。
- 本总览不把源码目录名、已链接库、已编译函数、运行线程、对端 ACK 和物理设备结果当作同一层事实。需要结论时，从对应报告的构建条件和实际主入口向下追。
