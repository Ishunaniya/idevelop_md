## 建议提交顺序（每步独立可回滚 + 全量编译验证「零 warning」）

1. **P3 全部**（纯注释，最安全，先清干净误导信息）→ 编译。
2. **P0 决策**落地（可能带出 P1-1 的阈值改动）→ 编译 + 现网回归。
3. **P1-2 / P1-3 / P1-4 / P1-5** 逐条修 → 编译。
4. **P2 死代码**分模块提交：P2-1(cc_deque) → P2-4/2-5/2-6/2-8(小范围) → P2-3(nw.c 大范围，单独提交重点验证) → P2-2/2-7。每次 `make clean && make` 确认零 warning、二进制正常。
5. 全部完成后跑一遍参考文档 F 章回归基线。
