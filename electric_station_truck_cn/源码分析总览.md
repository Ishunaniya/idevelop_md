## 1. 项目与报告入口

`bs_client` 是国内版车载换电客户端：从本机 CAN/GPS 服务与设备文件读取车辆和电池信息，维护共享状态，连接换电站完成登录、鉴权、参数设置和属性应答，再经本机命令、DO 文件及相应车型 CAN 路径输出控制和故障。换电站、本机服务、文件生产者、MCU/VCU及机械执行机构的完整实现不在本仓库。

源码仓库：`/home/tronlong/lyp/code/electric_station_truck_cn/`。下面三个目录是文档分类，不是三个独立源码仓库。

## 3. 源码目录与共同架构

```text
electric_station_truck_cn/              # 源码根目录
├── Makefile -> Makefile-EC200A
├── Makefile-EC200A / Makefile-EG25
├── sdk.mk                             # 仅两个自卸车提交有根目录文件
├── main.c                             # 启动、周期任务、信号、DI/DO
├── ini/                               # 部署样例
├── scripts/start_bs.sh                # 设备启动与保活
└── src/
    ├── app_mng/                       # 配置、身份、共享状态
    ├── batt_stand_client/             # 站端 TCP 与消息协议
    ├── can_server/                    # 本机 CAN/GPS 接入与 CAN 解析/发送
    ├── cmd/                           # 本机命令输出
    ├── fault/                         # 故障判定与报文
    ├── common/ / skt_res/ / net_utils/ # 文件、配置、时间与网络辅助
    └── iniparser/ / list/ / log/ / aes128/
```

三份详细报告分别给出本提交源码树，树中省略仓库已有的中间产物。目录存在、被构建收集、被入口调用和设备能力验证是不同层次。

```text
换电站 TCP ⇄ 站端收发线程 ─────────┐
本机 CAN(GPS) → 接收线程 ─────────┤
配置/DI/ACC → 初始化与主线程 ─────┤
                                  v
                    app_mng_t → bcc_ctrl_t 共享状态
                       │            │          │
                       v            v          v
                  站端属性回复   主循环控制   故障判定
                       │            │          │
                       v            └────┬─────┘
                  消息链表/send()        v
                               :16008 / DO / 车型 CAN 输出
                                         v
                                外部服务、控制器与机械机构
```

这是单进程内的逻辑职责关系，存在直接调用、共享字段与多个线程；没有据目录名虚构严格分层或通用事件总线。队列锁不覆盖整个状态；网络调用日志也不证明对端或机械执行完成。

## 4. 三个提交的实际差异

以下比较相应默认车型的活动路径；保留的其他车型另在各报告说明。

| 项目 | 重卡 `d67a4ac` | 旧自卸车 `e50ab6d` | 新 C `24d5f4f` |
| --- | --- | --- | --- |
| 本机输入 | CAN 三路 16002/16003/16004 | CAN 三路 + GPS 16005，四路全连接才读取 | 同旧自卸车 |
| ICCID | 活动函数始终返回固定占位串，SIM 代码被注释 | EC200A 调 SIM SDK；非 EC200A 用占位串 | 同旧自卸车 |

| 机器 VIN | 重卡初始化优先；主循环所有车型周期重试 | 默认自卸车初始化不优先；主循环周期重试 | 同旧自卸车 |
| 历史状态/自动迁移 | 无自卸车式恢复与反馈迁移写回链 | 恢复 INI，反馈迁移、变化时写回 | 同旧自卸车 |

| 本机命令内容 | 唤醒、状态、`CHINA_CAR`、保留区，无故障字段 | 增加故障等级与 64 位掩码 | 同旧自卸车 |
| 活动故障位 | 两类锁销/连接器反馈故障 | 42/43/44 | 33/34/35/36/42/43/44，部分位共用反馈 |
| DM1 | 重卡主循环先尝试发送、后重新判定 | 没有活动 DM1 发送函数 | 默认新 C 等级非零时发送；零等级不从此函数发清除帧 |
| 新 C T-Box ID CAN 输出 | 无活动新 C 路径 | 无该函数 | CAN0 `0x9AD32FF8` 分包 |

## 5. 核验方法与分支处理

本轮没有在源码工作区来回切分支。先确认本地分支与文档的完整提交一致，再用 `git show <提交>:<路径>` 独立阅读，先核对每个入口及业务闭环，随后用提交差异与文件哈希复查共享和变化部分。读取时源码工作区在新 C 分支，完成后仍在该分支且干净。

```sh
git -C /home/tronlong/lyp/code/electric_station_truck_cn rev-parse feat/heavy_truck_20241021 feat/dump_truck_20211021 feat/dump_truck_newc_20241031
git -C /home/tronlong/lyp/code/electric_station_truck_cn show d67a4acae0e9a48afcf5da196e130aacb5bc0a76:main.c
git -C /home/tronlong/lyp/code/electric_station_truck_cn diff e50ab6dfc0191e14e85aed4ea6f04a50a96c6a9d 24d5f4f87074b06300a9ad9c856b26c591cf983f -- main.c src/can_server/can_server.c
```

源码证据采用“提交:文件:行号”，避免把三个版本的链接都指向当前新 C 检出文件。后续需要目标构建时，为三个固定提交使用独立 detached worktree，分别管理 `.o/.d` 与二进制；重卡 `../../sdk.mk` 会受目录位置影响，必须另核对。未访问远端，不声称本地引用代表远端最新状态。

## 7. 验证结果与尚缺证据

对每个固定提交使用实际解析、打包代码运行主机最小探针，日志/控制接口使用无动作替身，属性应答调用真实打包函数，启用 AddressSanitizer：

| 请求 | 三个提交分别得到的结果 |
| --- | --- |
| 仅查询 ID 25（24 字节 BMS 编码） | 解析 0，回复 1 项、66 字节 |
| 显式查询 ID 0–29 | 解析 0，回复 30 项、190 字节 |
| 全量标记 255、不附 ID 列表 | 解析 0，传入 0 条目，回复打包 -1 |

三组用例在三个提交均完成预期检查，AddressSanitizer 未报告越界。这否定“首次全零检查导致普通回复分配过小”的特定推导，并确认所测全量查询失败；不证明任意输入、网络送达或硬件动作正确。

两个自卸车提交的历史读取均有不兼容指针警告；主机 `unsigned int` 为 4 字节、目标字段为 1 字节，相邻四字段偏移为 13/14/15/16。源码类型错误确认，具体设备表现仍待目标 ABI 和输入验证。

还未完成目标 SDK 全量构建、站端联调、车辆原始信号单位确认、本机服务端 ABI 检查、机械动作和设备并发压力验证。各报告第 11 节列出对应所需证据，第 12 节保留现场逐段取证方法。
