## ⚠️ 最终定稿（2026-06-16，覆盖下文第 4~6 节的过渡结论）

> 以下两点为最终落地实现，**与下文 §4「BYTE0→F / BYTE1→K 拆分」、§6 风险评估相冲突时，以本节为准**。
> 下文 §1~§7 保留作排查过程记录，不代表当前代码状态。

**1. K* 与 F* 均来自 BYTE0（不再拆 BYTE1）**
- 依据：客户《BCM参数 字段对接说明》三张图（`20260616-124254/124445/124458.png`）明确把 **K5~K12 状态、F5~F24 状态都标注为 `0x18FD0291` BYTE0** 的循环故障码。
- 这与 §2/§4 当时采用的协议图（`20260605-182443.png` 称 BYTE1=继电器K）**冲突**；经确认以"字段对接说明"为准。
- 代码现状：单一 `s_faultLastSeenMs`（BYTE0），`k5~k12` 与 `f5~f24` 都用 `isActive(n)` 查同一集合（= 改动前原始行为）。**§4 引入的双 map、BYTE1 解析、`relayFaultCode`/`activeRelayFaultCodes` 已全部回退。**
- 已知副作用（号段 {5,7,9,10,11,12} 重叠）：`BYTE0=9` 会同时点亮 `f9` 和 `k9`——这是单字节模型的固有结果，属预期。

**2. bcmErr（type7）已接入，走 `faultInfo.faultList`（字符串码）**
- 来源：复用已还原的 BYTE0 活跃集合，不重新解析 CAN。
- 码命名（依 `20260616-114007.png`）：保险丝 `BCMERRF%03d`、继电器 `BCMERRK%03d`；某序号同时落在 F/K 号段则两条都出（与指示灯一致）。
- 落地位置：`updateBcmFaults()` → `s_bcmFaultMap` → `rebuildFaultList()`，把 BCM 故障并入 `faultList`（type=`bcmErr`，code 为字符串）。**标量 `faultInfo.bcmErr` 维持 int 0 不变**（UI 无 QML 消费，显示走 faultList）。
- UI 侧：`formatFaultCodeText/ContentText` 参数 int→QVariant，新增 `bcmFaultContent()`；`FaultInfoTable`/`Gadget_FaultInfo.qml` 未改。
- 涉及文件追加：`skes-ui/skes-main_fork-lift/VehicleController.{h,cpp}`。

**仍待实机验证**：继电器故障到底走 BYTE0 还是 BYTE1。当前按三图取 BYTE0；若实机发现继电器码在 BYTE1，再议。

## 0. 背景 / 排查入口

用 `nanocat --sub --connect "tcp://127.0.0.1:19226" -A` 抓 dataengine 发布的实时状态（`filter_table`）。
观察到的关键字段：

```
faultInfo 段（统一故障列表）：全部为 0
  faultCount=0  userErr=0  vcuErr=0  driveMcuErr=0  steerMcuErr=0
  pumpMcuErr=0  bmsErr=0  bcmErr=0  maintenanceAlert=0  faultList="[]"

fuseBoxStatus 段（保险盒）：发现一个活跃故障
  k5~k12  全 0
  f5~f16  全 0
  f17 = 1     ← 唯一非零！保险丝 F17 故障
  f18~f24 全 0
```

**结论：VCU 说的"17"是真实存在的，它就是保险丝 F17 故障，但它走的是 `fuseBoxStatus` 这条通道，不是 `faultInfo.bcmErr` / `faultList`。两条通道是相互独立的。**

## 1. 系统里存在的两套"故障"通道（务必区分）

### 通道 A：`faultInfo` —— 统一故障列表（faultList）

由 `core/RealtimeStatusManager.cpp` 中的 `updateFaultEntry(realtime_status, type, code)` 维护。
- 故障类型 1~8 定义见 `faultTypeName()` / `faultTypeCode()`。
- 任意类型 `code != 0` 时加入 `s_faultMap`，并重建 `faultInfo.faultList`（按 type 升序）。
- `faultInfo.faultCount` = faultList 长度。

故障类型与解析来源对照表：

| type | 字段(code名) | 中文名 | CAN 来源 | 取值位置 | 是否已接入 |
|------|--------------|--------|----------|----------|------------|
| 1 | `userErr` | 用户提醒 | CAN1 `0x32D` | BYTE1 | ✅ |
| 2 | `vcuErr` | VCU故障 | CAN1 `0x32E` | BYTE1 | ✅ |
| 3 | `driveMcuErr` | 行走MCU故障 | CAN0 `0x0CFF0208` | BYTE4~5 小端 | ✅ |
| 4 | `steerMcuErr` | 转向MCU故障 | CAN0 `0x360` | BYTE1 | ✅ |
| 5 | `pumpMcuErr` | 油泵MCU故障 | CAN0 `0x0CFF0209` | BYTE4~5 小端 | ✅ |
| 6 | `bmsErr` | BMS故障 | CAN0 `0x0CFF8003` | BYTE0~6（任一非零触发，BYTE3 bit0~1 为严重等级） | ✅ |
| **7** | **`bcmErr`** | **BCM故障** | **无** | **—** | **❌ 未接入** |
| 8 | `maintenanceAlert` | 保养提示 | 内部判定 | 固定 code 8000 | ✅ |

**关键事实：type 7（BCM / bcmErr）只有定义，没有任何数据源。**
- `updateFaultEntry(..., 7, ...)` 在全代码中**从未被调用**。
- `realtime_status[...]["faultInfo"]["bcmErr"]` **没有任何写入语句**（只有 `bmsErr` 在写）。
- `SkesQtBridge.cpp` 用 `cInt("faultInfo","bcmErr")` 去读，但没人写，所以恒为默认值 0。

→ 这就是"即使 VCU/BCM 发故障，bcmErr 也永远是 0、faultList 里永远没有 BCM"的根因。

### 通道 B：`fuseBoxStatus` —— 保险盒/继电器状态（独立于 faultInfo）

由 CAN0 `0x18FD0291` 帧解析，结果写进 `fuseBoxStatus.*`（fuseFaultCode / k* / f* / activeFaultCodes 等），
**不进 faultInfo，也不进 faultList**。
F17 故障就是从这条通道来的。

## 2. 0x18FD0291 协议定义（来自 VCU 提供的协议图）

图片文件：`20260605-182443.png`（保存在 dataengine 工程根目录）

| 字节 | 协议定义 |
|------|----------|
| BYTE0 | 保险故障码（F1-FN，多个故障时循环发送） |
| BYTE1 | 继电器故障码（K1-KN，多个故障时循环发送） |
| BYTE2 | DI1~DI7 (Bit0~6) + 心跳 (Bit7) |
| BYTE3 | DO1~DO6 (Bit0~5)，DO1=大灯指示 |
| BYTE5 | C11 输出比例 |
| BYTE6 | C12 输出比例 |
| BYTE7 | BCM 软件版本（Seq4.15，存入 versionInfo.bcmSoftVersion） |

循环发送语义：多个故障时该字节轮流发各故障序号（如 K9+K12 → 9,12,9,12...）；
某故障恢复后其序号停止出现，超时 5 秒后从活跃集合移除；字节=0 表示该类全部恢复，立即清空。

**号段：**
- `K_FUSE_NUMS = {5,7,9,10,11,12}`（继电器）
- `F_FUSE_NUMS = {5,6,7,...,24}`（保险丝）
- ⚠️ 两者在 `{5,7,9,10,11,12}` 上**号段重叠** —— 这是后面 bug 与改动的关键。

## 3. 改动前代码的状态（0x18FD0291 handler）

位置：`core/RealtimeStatusManager.cpp`，`if (can_channel == 0 && can_id == 0x18FD0291 ...)` 块内。

改动前行为：
1. 只读 `can_data[0]`（BYTE0），存入 `fuseFaultCode`。
2. **BYTE1 完全没读**。
3. 用**单个 map** `s_faultLastSeenMs`（key=故障码）做活跃集合 + 超时淘汰。
4. `k5~k12 = isActive(n)`，`f5~f24 = isActive(n)` —— **K\* 和 F\* 都查同一份 BYTE0 数据**。
5. `activeFaultCodes` = 该 map 的排序键列表。

### 改动前存在的两个问题

**问题①：BYTE1（继电器 K\* 故障码）根本没解析** → 按协议本该从 BYTE1 来的 K1-KN 继电器故障，一个都收不到。

**问题②：K\* 和 F\* 共用 BYTE0 + 号段重叠，导致误判**
因为 `K_FUSE_NUMS` 与 `F_FUSE_NUMS` 在 {5,7,9,10,11,12} 重叠，且都查 BYTE0：
例如保险丝 F7 故障（BYTE0=7），`isActive(7)` 为真 → 会**同时把 f7 和 k7 都点亮**，K7 是误报。

> 注意：原代码注释里写的是"BYTE0：保险/继电器故障循环码...例如K9+K12故障→依次发9,12"，
> 即**原作者当时认为 K 和 F 都从 BYTE0 发**。这与协议图（K 走 BYTE1）**直接冲突**，
> 是本次改动最大的不确定点（见第 6 节风险）。

## 4. 本次改动内容（已实施 + 已编译通过）

> 编译：已用 aarch64 工具链 `make` 成功链接出 `vehicleDataEngine`，无报错。

### 4.1 `core/RealtimeStatusManager.cpp` —— 拆成两个独立故障集合

**(a) 声明处**：把单个 `s_faultLastSeenMs` 拆成两个，并新增公共函数：

```cpp
// 0x18FD0291 BYTE0=保险故障码(F*)、BYTE1=继电器故障码(K*)，分别独立追踪
// （F*与K*序号存在重叠：5/7/9/10/11/12，必须分两个集合，否则会互相误判）
static std::unordered_map<int, int64_t> s_fuseFaultLastSeenMs;   // F* 保险故障 (BYTE0)
static std::unordered_map<int, int64_t> s_relayFaultLastSeenMs;  // K* 继电器故障 (BYTE1)

// 循环故障码集合更新：code!=0 记录/刷新时间戳；超时未再出现则移除；code=0 立即清空
static void updateCircularFaultSet(std::unordered_map<int, int64_t>& seenMap,
                                   int code, int64_t now_ms, const char* tag) {
    if (code == 0) {
        if (!seenMap.empty()) { /* 清空 + 日志 */ seenMap.clear(); }
    } else {
        seenMap[code] = now_ms;
    }
    // 超时淘汰：超过 FUSE_FAULT_TIMEOUT_MS(5s) 未出现则移除
    for (auto it = seenMap.begin(); it != seenMap.end(); ) {
        if (now_ms - it->second > FUSE_FAULT_TIMEOUT_MS) it = seenMap.erase(it);
        else ++it;
    }
}
```

**(b) handler 处**：
- 新增读取 `relayFaultCode = can_data[1]`（BYTE1），写入 `fuseBoxStatus.relayFaultCode`。
- `updateCircularFaultSet(s_fuseFaultLastSeenMs, fuseFaultCode=BYTE0, ...)`
- `updateCircularFaultSet(s_relayFaultLastSeenMs, relayFaultCode=BYTE1, ...)`
- `k5~k12 = isRelayActive(n)`（查 BYTE1 集合）
- `f5~f24 = isFuseActive(n)`（查 BYTE0 集合，**与改动前完全一致**）
- 输出 `activeFaultCodes`（F\*，含义不变）+ 新增 `activeRelayFaultCodes`（K\*）

### 4.2 `profiles/forklift/realtime_status.json` —— 补初始值

```json
"relayFaultCode": 0,            // 新增
```

## 5. 改动对"原有保险盒功能"的影响评估

### F\* 保险丝（f5~f24）：✅ 完全不受影响

| 对比项 | 改之前 | 改之后 |
|--------|--------|--------|
| 数据来源 | BYTE0 | BYTE0 **相同** |
| 非0记录 / =0清空 / 5s超时淘汰 | 有 | 有 **逻辑一致** |
| f5~f24 输出 | `isActive(n)` 查 BYTE0 | `isFuseActive(n)` 查 BYTE0 **相同** |

只是把 `s_faultLastSeenMs` 改名为 `s_fuseFaultLastSeenMs`、把内联逻辑抽成 `updateCircularFaultSet()`，**行为零变化**。
之前抓到的 `f17=1` 行为一致，不会坏。

### K\* 继电器（k5~k12）：⚠️ 数据来源由 BYTE0 改为 BYTE1（行为已变）

这是唯一的功能性行为变化，对错取决于固件实际在哪个字节发继电器码（见第 6 节）。

## 6. 未决风险与待验证项（**后续分析重点**）

### 核心矛盾
- **协议图**：BYTE0=保险F\*，BYTE1=继电器K\*。
- **原代码注释**：K 和 F 都从 BYTE0 发。
- 两者冲突，目前**无法仅凭手头数据判定谁对**。

### 两种可能后果
| 情况 | 若协议图正确（K 走 BYTE1） | 若原注释正确（K 也走 BYTE0） |
|------|----------------------------|------------------------------|
| 本次改动 | ✅ 修对了，且消除了号段重叠误判 | ❌ k5~k12 会恒为 0（BYTE1 固件不填） |

### 待办：用真实报文验证
- 抓一帧 `0x18FD0291` 原始 8 字节（`candump can0 | grep 18FD0291`，或 nanocat 看原始帧）。
- 制造一个**继电器**故障，观察是 **BYTE0** 还是 **BYTE1** 出现非零序号。
- 确认后定稿；若发现 K 实际走 BYTE0，则需回退 K\* 部分。

### 另一处尚未处理（独立决策）
`faultInfo.bcmErr`（type 7）这条统一故障列表通道**本次没接**。
保险/继电器故障目前只进 `fuseBoxStatus`，不进 `faultList`。
若 UI「故障信息」列表也要显示 BCM（保险/继电器）故障，需要额外加：
```cpp
updateFaultEntry(realtime_status, 7, <bcm故障码>);
```
是否要做、以及 bcmErr 的"code"取什么值（保险码？继电器码？合并？），需进一步确认需求。

```cpp
// type 5 油泵MCU故障 —— CAN0 0x0CFF0209 BYTE4~5 小端
if (can_channel == 0 && can_id == 0x0CFF0209 && data_length >= 6) {
```

```cpp
static std::unordered_map<int, int64_t> s_relayFaultLastSeenMs;  // K* 继电器故障 (BYTE1)

static void updateCircularFaultSet(std::unordered_map<int, int64_t>& seenMap,
                                   int code, int64_t now_ms, const char* tag) {
    if (code == 0) {
        if (!seenMap.empty()) {
            std::printf("[保险盒] %s 故障已全部恢复(BYTE=0)，清空故障表\n", tag);
            seenMap.clear();
        }
    } else {
        seenMap[code] = now_ms;
    }
    for (auto it = seenMap.begin(); it != seenMap.end(); ) {
        if (now_ms - it->second > FUSE_FAULT_TIMEOUT_MS) {
            std::printf("[保险盒] %s 故障码=%d 超时未出现，标记为已恢复\n", tag, it->first);
            it = seenMap.erase(it);
        } else {
            ++it;
        }
    }
}
```

### C.2 handler 故障码段

**改动前（只读 BYTE0，K\*/F\* 共用单 map）：**
```cpp
uint8_t fuseFaultCode = can_data[0];
realtime_status["chache"]["fuseBoxStatus"]["fuseFaultCode"] = (int)fuseFaultCode;

int64_t now_ms = std::chrono::duration_cast<std::chrono::milliseconds>(
    std::chrono::steady_clock::now().time_since_epoch()).count();

if (fuseFaultCode == 0) {
    if (!s_faultLastSeenMs.empty()) { s_faultLastSeenMs.clear(); }
} else {
    s_faultLastSeenMs[fuseFaultCode] = now_ms;
}
for (auto it = s_faultLastSeenMs.begin(); it != s_faultLastSeenMs.end(); ) {
    if (now_ms - it->second > FUSE_FAULT_TIMEOUT_MS) it = s_faultLastSeenMs.erase(it);
    else ++it;
}
auto isActive = [&](int n) { return s_faultLastSeenMs.count(n) > 0; };

// K* 和 F* 都查 BYTE0（问题所在）

// ... k7/k9/k10/k11/k12 同理 ...

    realtime_status["chache"]["fuseBoxStatus"]["f"+std::to_string(n)] = isActive(n);
}
// activeFaultCodes = sorted(s_faultLastSeenMs keys)
```

**改动后（BYTE0→F\*，BYTE1→K\*，两 map 分离）：**
```cpp
uint8_t fuseFaultCode  = can_data[0];                          // BYTE0: 保险故障码 F*
uint8_t relayFaultCode = (data_length >= 2) ? can_data[1] : 0; // BYTE1: 继电器故障码 K*
realtime_status["chache"]["fuseBoxStatus"]["fuseFaultCode"]  = (int)fuseFaultCode;
realtime_status["chache"]["fuseBoxStatus"]["relayFaultCode"] = (int)relayFaultCode;

int64_t now_ms = std::chrono::duration_cast<std::chrono::milliseconds>(
    std::chrono::steady_clock::now().time_since_epoch()).count();

updateCircularFaultSet(s_fuseFaultLastSeenMs,  fuseFaultCode,  now_ms, "保险丝F");
updateCircularFaultSet(s_relayFaultLastSeenMs, relayFaultCode, now_ms, "继电器K");

auto isFuseActive  = [&](int n) { return s_fuseFaultLastSeenMs.count(n)  > 0; }; // F* ← BYTE0
auto isRelayActive = [&](int n) { return s_relayFaultLastSeenMs.count(n) > 0; }; // K* ← BYTE1

// K继电器状态（来自BYTE1）
realtime_status["chache"]["fuseBoxStatus"]["k5"]  = isRelayActive(5);
realtime_status["chache"]["fuseBoxStatus"]["k7"]  = isRelayActive(7);
realtime_status["chache"]["fuseBoxStatus"]["k9"]  = isRelayActive(9);
realtime_status["chache"]["fuseBoxStatus"]["k10"] = isRelayActive(10);
realtime_status["chache"]["fuseBoxStatus"]["k11"] = isRelayActive(11);
realtime_status["chache"]["fuseBoxStatus"]["k12"] = isRelayActive(12);
// F保险丝状态（来自BYTE0）
for (int n : F_FUSE_NUMS) {
    realtime_status["chache"]["fuseBoxStatus"]["f"+std::to_string(n)] = isFuseActive(n);
}
// activeFaultCodes = sorted(F*),  activeRelayFaultCodes = sorted(K*)
```

> **差异小结**：F\*（fuseFaultCode/f5~f24/activeFaultCodes）的数据源、记录/清空/超时逻辑、输出**完全一致**；
> 唯一变化是 K\*（k5~k12）由 `isActive`(BYTE0) 改为 `isRelayActive`(BYTE1)，并新增 `relayFaultCode` / `activeRelayFaultCodes`。
